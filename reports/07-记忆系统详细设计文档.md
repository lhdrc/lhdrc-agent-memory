## 0. 已锁定的设计决策（ADR）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 记忆 = 可寻址文档树（`mem://{ws}/...`）+ 零 LLM typed-edge 知识图谱 + 原子事实 | 路径寻址可审计、关系查询确定可答、向量负责语义 |
| D2 | 写入 ADD-only（只增不覆盖），更新语义由 merge_op + 检索排序承载 | 避免写入端 LLM diff 出错（Mem0 洞见） |
| D3 | L0/L1/L2 分层写入时异步生成，读取时按需加载 | 省 token（OpenViking 实证 -91%） |
| D4 | **MVP 向量策略：MySQL fulltext(BM25) + 确定性图谱检索先行，Qdrant 向量第二阶段引入** | df-app 用 MySQL 无 pgvector；零新基础设施最快落地 |
| D5 | **提取 LLM：服务端轻量模型调用（抽象 LLMProvider），复用现有轻量模型通道，不依赖沙箱** | 现有"网关"是沙箱 harness，不适用服务端轻量提取 |
| D6 | **摄取边界：df-memory 直接读 df-app 库（只读账号 + 增量游标）** | DB 是消息的**唯一有序真源**（entry_index 单调）；Kafka 有乱序/丢序风险，读库最可靠（用户决策） |
| D7 | 多租户隔离由存储层强制（workspace_id 参与主键/唯一键 + DAO 强制注入） | GBrain/OpenViking 架构保证优于 UI 隐藏 |
| D8 | 成本：search mode 档位 + cost cap + LLM kill-switch + 降级链 | GBrain 成本一等公民 |
| D9 | 审计：memory_diff 变更日志 + trace_id 贯穿 | 团队共享记忆底线 |
| D10 | **服务形态：独立项目 df-memory**，独立仓库/独立部署/独立库，**对外暴露 REST + MCP**，df-app 作为调用方接入 | 用户决策：独立项目、对外接口、df 调用 |
| D11 | **存储独立**：df-memory 使用自己的 MySQL 实例/库（`df_memory`），不依赖 df-app 的库 | 独立项目的数据边界；摄取只读 df-app 库，写入全在自有库 |
| D12 | **对外鉴权：服务端 API Token（服务间调用）+ MCP 工具** | 独立服务不能被 df-app 内部机制白嫖；df 侧持有 token 调用 |

## 1. 技术栈

> 独立项目定位：**df-memory 是一个可独立部署的服务**，与 df-app 完全解耦。df-app 通过 HTTP 调用它；它只读 df-app 库做摄取、写入全在自己库。内部仍沿用 df-app 的四层工程规范（代码习惯一致，便于团队维护）。

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Java 17 | 与 df-app 技术栈一致（仅语言一致，不依赖其代码） |
| 框架 | Spring Boot 3.x | 独立启动 |
| 分层 | `df-memory-api` / `df-memory-application` / `df-memory-infrastructure` / `df-memory-starter` | 沿用四层规范，边界清晰 |
| 关系存储 | **独立 MySQL（实例或逻辑库 `df_memory`）** | 节点/边/事实/审计/经验全关系型（D11） |
| 词法检索 | MySQL InnoDB FULLTEXT（ngram 解析器支持中文） | MVP 检索主力之一 |
| 图谱检索 | MySQL `mem_edge` 邻接遍历（SQL join / 递归 CTE） | 零 LLM 关系查询 |
| 向量存储（P2） | Qdrant（可插拔 BaseVectorStore） | 第二阶段引入 |
| 摄取源 | **只读 df-app 库**（专用只读账号；`chat_message_log`/`work_item`/`work_artifact`/`work_phase`） | D6：DB 有序真源，增量游标轮询 |
| 异步 | Spring 异步 + 自建内存队列（MVP）/ Redis Stream（P2） | 摄取/提取异步化 |
| 定时 | **自建调度（Spring Scheduling / 可选 Quartz）** | 独立项目不依赖 df-app Crane |
| LLM | 抽象 `LLMProvider`，默认轻量模型（HTTP + Bearer token，OpenAI 兼容） | D5：服务端轻量调用 |
| 检索接口 | REST + MCP（Java MCP SDK） | 对外暴露（D10） |
| 对外鉴权 | **服务端 API Token（服务间）+ MCP**；内置 admin 登录 | D12：独立认证，不依赖 df SSO |
| 配置 | 独立配置文件 + 可选配置中心（预留接口） | 不绑定 df-app Lion |
| 监控 | 自建指标 + 结构化日志（workspace_id/session_id/trace_id） | 独立可观测 |
| ORM | MyBatis（MyBatis Generator 生成） | 独立库 schema 自管 |
| 迁移 | Flyway 管理 schema 版本 | df-memory 独立迁移链 |
| 部署 | Docker + 独立进程；`/health` 健康检查 | 独立部署（D10） |

## 2. 数据模型（完整 DDL）

> 所有表带 `workspace_id`，参与唯一键，强制租户隔离。DDL 以 Flyway 迁移维护。

```sql
-- ============ 1. 记忆节点（文档树） ============
CREATE TABLE mem_node (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  workspace_id  BIGINT        NOT NULL,
  node_id       VARCHAR(64)   NOT NULL,          -- 全局唯一 nodeId（UUID）
  path          VARCHAR(512)  NOT NULL,          -- 确定性路径 mem://{ws}/issues/{id}/...
  node_type     VARCHAR(32)   NOT NULL,          -- DIRECTORY / DOC / ISSUE_ROOT / ...
  schema_type   VARCHAR(32)   NOT NULL,          -- requirement/decision/lesson/experience/session/profile/skill
  title         VARCHAR(255)  NOT NULL,
  parent_path   VARCHAR(512)  NULL,              -- 父节点路径（根为 NULL）
  abstract_text LONGTEXT      NULL,              -- L0
  overview_text LONGTEXT      NULL,              -- L1
  content       LONGTEXT      NULL,              -- L2 全文
  version       INT           NOT NULL DEFAULT 1, -- merge 后递增
  status        TINYINT       NOT NULL DEFAULT 1, -- 1=active 2=archived 3=stale
  source_ref    VARCHAR(128)  NULL,              -- 关联 work_item.id / session_id
  created_by    VARCHAR(64)   NOT NULL,
  agent_id      VARCHAR(64)   NULL,
  created_at    DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_node_path (workspace_id, path),
  KEY idx_node_parent (workspace_id, parent_path),
  KEY idx_node_source (workspace_id, source_ref),
  KEY idx_node_type  (workspace_id, schema_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============ 2. 图谱边（零 LLM 生成） ============
CREATE TABLE mem_edge (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  workspace_id  BIGINT       NOT NULL,
  from_path     VARCHAR(512) NOT NULL,
  to_path       VARCHAR(512) NOT NULL,
  link_type     VARCHAR(32)  NOT NULL,  -- decided/produced_by/works_on/references/belongs_to/mentions/...
  link_source   VARCHAR(16)  NOT NULL,  -- wikilink/markdown/mention/verb
  link_kind     VARCHAR(16)  NULL,      -- plain/typed_ner
  created_by    VARCHAR(64)  NOT NULL,
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_edge (workspace_id, from_path, to_path, link_type, link_source),
  KEY idx_edge_to   (workspace_id, to_path),
  KEY idx_edge_type (workspace_id, link_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============ 3. 原子事实（ADD-only） ============
CREATE TABLE mem_fact (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  workspace_id   BIGINT        NOT NULL,
  fact_id        VARCHAR(64)   NOT NULL,
  scope          VARCHAR(16)   NOT NULL,          -- issue/session/user/global
  scope_id       VARCHAR(64)   NOT NULL,          -- issueId/sessionId/userId
  text           TEXT          NOT NULL,          -- 自包含事实
  text_hash      CHAR(32)      NOT NULL,          -- MD5
  attributed_to  VARCHAR(64)   NULL,              -- 说话者 user_id/agent_id
  user_id        VARCHAR(64)   NULL,
  agent_id       VARCHAR(64)   NULL,
  issue_id       VARCHAR(64)   NULL,
  session_id     VARCHAR(64)   NULL,
  event_type     VARCHAR(32)   NULL,              -- decision/meeting/preference/lesson/...
  status         TINYINT       NOT NULL DEFAULT 1, -- 1=active 2=expired 3=archived
  created_at     DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at     DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_fact_hash (workspace_id, text_hash),
  KEY idx_fact_scope (workspace_id, scope, scope_id),
  KEY idx_fact_issue (workspace_id, issue_id),
  KEY idx_fact_user  (workspace_id, user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============ 4. 实体 + 链接（P2 启用，MVP 可建表不用） ============
CREATE TABLE mem_entity (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  workspace_id    BIGINT       NOT NULL,
  entity_id       VARCHAR(64)  NOT NULL,
  entity_type     VARCHAR(16)  NOT NULL,   -- PROPER/TOPIC/IDENTIFIER/QUOTED
  entity_text     VARCHAR(255) NOT NULL,
  normalized_text VARCHAR(255) NOT NULL,   -- 归一化（小写/去空格）
  linked_fact_ids JSON         NULL,       -- [factId,...]
  created_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_entity (workspace_id, normalized_text)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============ 5. 变更审计（memory_diff） ============
CREATE TABLE mem_change_log (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  workspace_id  BIGINT       NOT NULL,
  ref_type      VARCHAR(16)  NOT NULL,   -- node/fact/edge/experience
  ref_id        VARCHAR(64)  NOT NULL,
  action        VARCHAR(16)  NOT NULL,   -- add/update/delete/merge/archive
  before_text   LONGTEXT     NULL,
  after_text    LONGTEXT     NULL,
  actor         VARCHAR(64)  NOT NULL,   -- user_id / agent_id
  trace_id      VARCHAR(64)  NOT NULL,
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  KEY idx_change_ref (workspace_id, ref_type, ref_id),
  KEY idx_change_trace (trace_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============ 6. 经验/技能结晶 ============
CREATE TABLE mem_experience (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  workspace_id  BIGINT       NOT NULL,
  exp_id        VARCHAR(64)  NOT NULL,
  issue_id      VARCHAR(64)  NULL,               -- 来源 issue
  trigger_text  TEXT         NOT NULL,           -- 触发条件（用于复用匹配）
  procedure_json JSON        NOT NULL,           -- [{step, detail}]
  applicability TEXT         NULL,               -- 适用边界
  result_json   JSON         NULL,               -- 结果/收益
  source_trajectory_ids JSON NULL,               -- 来源轨迹/会话
  eta_score     DECIMAL(5,2) NOT NULL DEFAULT 0, -- 复用度/置信
  status        TINYINT      NOT NULL DEFAULT 1, -- 1=draft 2=active 3=archived
  created_by    VARCHAR(64)  NOT NULL,
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  UNIQUE KEY uk_exp (workspace_id, exp_id),
  KEY idx_exp_issue (workspace_id, issue_id),
  FULLTEXT KEY ft_exp_trigger (trigger_text) WITH PARSER ngram
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============ 7. 配置与维护状态 ============
CREATE TABLE mem_config (
  workspace_id BIGINT      NOT NULL,
  cfg_key      VARCHAR(64) NOT NULL,
  cfg_value    TEXT        NOT NULL,
  updated_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (workspace_id, cfg_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE mem_ingest_cursor (
  workspace_id  BIGINT       NOT NULL,
  session_id    VARCHAR(64)  NOT NULL,
  last_entry_index BIGINT    NOT NULL DEFAULT 0,  -- chat_message_log 游标
  last_issue_id VARCHAR(64)  NULL,
  updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (workspace_id, session_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE mem_job_state (
  job_type   VARCHAR(32) NOT NULL,   -- maintain/dedup/consolidate/contradiction
  run_key    VARCHAR(128) NOT NULL,  -- 如 workspace:12
  state      VARCHAR(32) NOT NULL,   -- running/done/failed
  run_at     DATETIME(3) NOT NULL,
  finished_at DATETIME(3) NULL,
  PRIMARY KEY (job_type, run_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**与 df-app 现有表的关系**：
- `chat_message_log(session_id, entry_index)`：摄取游标源；
- `work_item(id, session_id, workspace_id, status, current_phase)`：issue → 记忆主干映射（`mem_node.source_ref = work_item.id`）；
- `work_artifact(work_id, artifact_type, content)`：PLAN/TEST → 记忆节点来源；
- `work_phase`：阶段事件触发 experience 提炼；
- 现有 `workspace_memory` 表：迁移或废弃，由 `mem_node` 承接。

### 3.5 LLMProvider 抽象（D5）

```java
public interface LLMProvider {
    /** 单遍 ADD-only 提取事实 + 实体。一次调用。 */
    ExtractResult extractFacts(ExtractContext ctx);

    /** L0 摘要。 */
    String generateAbstract(String content, String schemaType);

    /** L1 概览（聚合子目录 L0）。 */
    String generateOverview(List<String> childAbstracts);

    /** 去重判定：duplicate / supersede / independent（LLM 降级路径）。 */
    DedupDecision judgeDedup(String existingText, String candidateText);

    /** 经验提炼。 */
    ExperienceResult refineExperience(ExperienceContext ctx);
}

public record ExtractContext(
    String workspaceId, String scope, String scopeId,
    List<ChatMessage> recentMessages,     // 最近 N 条
    List<String> existingFacts,           // 相似现有事实（防幻觉/去重）
    String observationDate                // 相对时间锚点
) {}

public record ExtractResult(List<ExtractedFact> facts, List<ExtractedEntity> entities) {}

public record ExtractedFact(
    String text, String attributedTo, String issueId,
    String sessionId, String eventType
) {}

public record ExtractedEntity(String text, String entityType) {}
```

**LLMProvider 默认实现（`OpenAiCompatibleLLMProvider`）**：走现有轻量模型通道（HTTP + Bearer token，OpenAI 兼容格式），`response_format=json_object`，温度 0。所有调用点 cost 统计 + kill-switch + 降级链：
- `extractFacts` 失败 → 返回空事实（不阻塞主链路）；`infer=false` 模式原样存储；
- `judgeDedup` 失败 → cosine（P2）/BM25 相似度阈值兜底；
- `generateAbstract`/`generateOverview` 失败 → 取 content 前 N 字符。

## 4. 模块详细设计

### 4.1 ingest 摄取模块（application/ingest）

**职责**：**只读 df-app 库**，增量消费 `chat_message_log` 与 `work_item`/`work_artifact`/`work_phase`，转化为记忆写入自有库。

**方案（D6）**：

```
[Gate 层] MemIngestScheduler（自建调度，每 30s）
  → 扫描 df-app 库 active sessions（mem_ingest_cursor 维护游标）
  → SELECT * FROM df_app.chat_message_log
       WHERE session_id=? AND entry_index > last_entry_index
       ORDER BY entry_index ASC LIMIT 500
  → 按 session 聚合 → 分组（每 50 条或 30min 一组）
  → 提交异步任务：ExtractTask
  → 推进 cursor
```

**为什么要读库而不是走 Kafka**（D6 决策依据）：
- `chat_message_log.entry_index` 是**单调有序的毫秒时间戳**，DB 查询天然保序、可断点续传；
- Kafka 有乱序/重复投递风险，对"记忆顺序"敏感的场景（经验轨迹、时间推理）不可靠；
- df-memory 是独立服务，读库是**只读耦合**——用一个只读账号即可，不需要 df-app 配合改任何代码。

**数据源访问**：`infra/source/` 配置独立数据源 `df-app-source`（只读账号 `df_memory_reader`，`READ ONLY` 权限），只允许 SELECT，杜绝写 df-app 库的可能。主库/读副本可选。

**关键方法**：

```java
public class MemIngestService {
    /** 增量轮询一个 session 的新消息，返回游标推进数。 */
    public int pollSession(String workspaceId, String sessionId);

    /** 处理一批消息：写 session 节点 + 触发提取。 */
    public void processBatch(IngestBatch batch);
}
```

**边界处理**：
- 消息按 `message_type` 过滤：仅 `USER_MESSAGE` 与 `CHUNK`（最终回复聚合）进入提取；`ERROR`/`DONE`/系统消息仅记 context；
- 敏感字段打码：df-memory 侧独立维护 `sensitive.mask.values` 配置（落 `mem_fact` 前脱敏）；
- session → issue 映射：`work_item.session_id = session_id` 查询（只读 df-app 库）；无 work 的 session 归入 `scope=session`；
- 断点续传：`mem_ingest_cursor`（自有库）每批提交；失败批不推进游标，下轮重试；
- 幂等：`mem_fact.unique(workspace_id, text_hash)` 天然防重复；
- **df-app 库不可用时**：本轮跳过不推进游标，下轮重试（记录告警），不影响对外查询接口。

**Job**：`MemIngestJob`（每 30s，自建调度单实例）；`MemIngestCompensationJob`（每小时，扫停滞 cursor）。

### 4.2 extract 提取模块（application/extract）

**职责**：从消息/产物提取原子事实 + 实体；生成 L0/L1 分层。

**流程**：

```
ExtractTask
  → [快路径] 查询相似现有事实（BM25 检索 scope 内 top5）

```

**提取 prompt 规格**（`infra/llm/prompts/` 资源，版本管理，即"prompt 即规格"）：

```
1. 只提取有证据的独立事实；无证据不提取。
```

### 4.4 graph 图谱模块（application/graph）

**职责**：零 LLM 正则建 typed edges；关系查询。

**（1）建边（写入钩子，零 LLM）**

每次 `createNode/updateNode` 后触发 `buildEdges(path)`：

```
extractEntityRefs(content) 四 pass（GBrain 模式）：
  ① [Text](path) markdown 链接
  ② [[path|Display]] qualified wikilink
  ③ [[path]] wikilink
  ④ 提及模式（{{entity}} 占位或 mention 词表）
先 stripCodeBlocks；masked-ranges 防双发

inferLinkType(path, target, content) 零 LLM 正则（link_type 推断）：
  - target 是 decisions/*        → 'decided'
  - target 是 issues/{id}/*      → 'references'
  - 动词规则（GBrain 风格）：
      FOUNDED_RE / DECIDED_RE / WORKS_ON_RE / PRODUCED_BY_RE
  - person 节点提到 → 'works_on'/'mentions'
  - 同一 issue 内 session 节点 → 'belongs_to'（由 parent 结构直接推导）
```

**（2）关系查询 arm**

```
parseRelationalQuery(query)   // 确定性，零 LLM
  → 识别 seed 实体 + 关系动词（"谁在 issue#123 上做过决策" → seed=issue#123, verb=decided）
  → engine.traverseRelations(workspaceId, fromSeed, linkTypes, depth=2)
  → 批量 hydrate 为 RetrievalResult
fail-open：解析失败返回空 arm + audit 行，不破坏热路径
```

**关键方法**：

```java
public class MemoryGraphService {
    /** 零 LLM 建边。 */
    public int buildEdges(String workspaceId, String nodePath);

    /** 邻接遍历（depth ≤ 2）。 */
    public List<GraphHit> traverseRelations(String workspaceId,
        String seedPath, List<String> linkTypes, int depth);

    /** 关系查询 arm（供 retrieve 调用）。 */
    public List<RetrievalResult> relationalRecall(String workspaceId, String query);
}
```

**SQL（邻接遍历，MVP 用两次 join 代替递归 CTE 保证 MySQL 兼容）**：

```sql
-- depth=1
SELECT e.to_path, e.link_type, n.title
FROM mem_edge e JOIN mem_node n ON n.workspace_id=e.workspace_id AND n.path=e.to_path
WHERE e.workspace_id=? AND e.from_path=? AND e.link_type IN (...);
-- depth=2：再对 to_path 作为 from_path 一次 join
```

### 4.5 dedup 去重模块（application/dedup）

```
    append    → 追加（lesson/experience 列表类）
  合并后 version 递增，写 mem_change_log(action=merge, before/after)
```

### 4.6 retrieve 检索模块（application/retrieve）— 核心

**（1）完整链路（MVP）**：

```
RetrieveRequest
  → 意图分类（零 LLM 正则）：issue/experience/person/general 四桶
      experience 意图 → 额外走 mem_experience 检索
  → 混合召回（并行）：
      ① keyword 通道：MySQL FULLTEXT(ngram) 查 mem_node.title/content + mem_fact.text
      ② graph 通道：relationalRecall（关系查询时）
      ③ path 通道：确定性路径匹配（query 是已知路径前缀）
  → RRF 融合（k=60）：score = Σ 1/(60 + rank_i)
  → 归一化 + 调权：
      - source-tier boost（project 共享 > issue > session）
      - hotness 混合（recency）：hotness = sigmoid(log1p(ref_count)) × exp(-decay×age)，半衰期 7 天
      - 目录 dominance：目录分须超最大子分 ×1.2 才作为候选（OpenViking）
  → 目录级预筛：优先定位高分目录子树，结果附 .abstract/.overview
  → 分层加载：结果默认只带 L0/L1 snippet；loadDetail=true 才取 L2
  → 排序去重（同 path 取最佳）→ 返回
```

**（2）BM25 归一化（Mem0 自适应 sigmoid）**：

```
normalize_bm25 = 1 / (1 + exp(-steepness × (raw - midpoint)))
midpoint/steepness 按查询词数自适应：
  ≤3: (5.0, 0.7)   ≤6: (7.0, 0.6)   ≤9: (9.0, 0.5)
  ≤15: (10.0, 0.5)  >15: (12.0, 0.5)
```

**（3）融合公式（MVP 确定性版本，无向量）**：

```
final = 0.55 × rrf(keyword) + 0.30 × rrf(graph) + 0.15 × hotness
      （relation 意图时 graph 权重升到 0.55）
threshold 前置：单一通道分 < floor 的直接剔除
```

**（4）意图分类（零 LLM 正则）**：

```java
public enum Intent { ISSUE, EXPERIENCE, PERSON, GENERAL }

public Intent classifyIntent(String query) {
    // 正则三桶：
    //   ISSUE: #issueId / issue\d+ / "issue 123" 等
    //   EXPERIENCE: 类似/做过/怎么弄/方案/复用/踩坑/经验 等
    //   PERSON: 谁/Alice/成员名（词表）
    // 偏 GENERAL（false positive 浪费 token > false negative）
}
```

**（5）检索分阶段可替换**：每个通道独立接口（`RetrievalChannel`），P2 加 vector 通道只需新增实现 + 调 RRF 权重，不动主流程。

**关键方法**：

```java
public class RetrievalOrchestrator {
    public RetrieveResponse retrieve(String workspaceId, RetrieveRequest req);
}

public interface RetrievalChannel {
    List<RetrievalResult> recall(RetrieveContext ctx);
    double weight(Intent intent);           // 融合权重
    boolean applicable(Intent intent);
}
```

**MVP 三个通道实现**：`KeywordChannel`（MySQL FULLTEXT）、`GraphChannel`（关系召回）、`PathChannel`（确定性路径）。

## 6. 简易实现方案（MVP 优先，分阶段）

> 每阶段可独立上线、可验证。与 df-app 演进风格一致。

### Phase 0 — 基础设施（≈0.5-1 人周）
- 独立仓库 `df-memory` + Flyway 初始化 7 张表（自有库 `df_memory`）；
- 四层骨架 + 配置 + API Token 鉴权骨架 + `/health`；
- **验收**：服务独立启动，健康检查通过，`mem_node` 可手工插入。

### Phase 1 — MVP：文档树 + 摄取 + 检索（BM25+图谱+路径）（≈2-3 人周）
- ingest：`MemIngestJob` 增量轮询 **df-app 库** `chat_message_log` → 建 issue/session 节点（原样存储，**无 LLM**）；
- graph：零 LLM 建边（markdown/wikilink/verb 正则）；
- retrieve：keyword(FULLTEXT) + graph + path 三通道 + RRF + 归一化 + hotness；
- 前端：df-gateway 反代 `/memory/**`，`tree/ls/find` 记忆浏览器 + 检索页；
- **验收**：issue 详情页展示记忆树；`find` 能命中 BM25 关键词与路径；关系查询"谁在 issue 上做过决策"可答。

### Phase 2 — 提取与分层（LLM 引入）（≈2-3 人周）
- LLMProvider 接通轻量模型通道；
- extract：ADD-only 单遍提取事实 + 实体；
- layer：L0/L1 异步生成；
- dedup：BM25 快路径 + LLM judge（可选）；
- 成本控制：CostGuard + search mode 档位；
- **验收**：事实从消息自动提炼；检索默认只带 L0/L1；成本熔断生效。

### Phase 3 — 向量与实体（≈1-2 人周）
- Qdrant + BaseVectorStore 抽象；
- 向量通道加入 RRF（权重重调）；
- 实体提取 + `mem_entity` 链接 + 实体 boost；
- **验收**：语义检索命中"没打关键词但意思相近"的内容；实体查询 boost 生效。

### Phase 4 — 经验飞轮（≈2 人周）
- experience：issue 完成触发提炼 + 复用注入；
- maintain：dedup/layer/consolidate/contradiction/stale 五个 Job；
- **验收**：完成 issue → 提炼经验；新建同类 issue 检索时命中经验并注入。

### Phase 5 — 治理完善（≈1-2 人周）
- 多租户细化（agent 隔离、记忆可见性）；
- 审计查询 + observer 指标 + 反馈修正（MemFeedback 语义）；
- MCP 工具全量；
- **验收**：权限 fuzz 零泄漏；审计可回滚；MCP 可接入 agent。

**依赖顺序**：P0 → P1 → (P2 ∥ P3 部分) → P4 → P5。P2/P3 可并行推进（P3 依赖 P2 的实体提取）。

## 8. df-app 接入方式（外部调用方视角）

df-memory 是独立服务，df-app 是它的**调用方 + 数据源**。两者关系：

```
df-app（df-gateway / 沙箱 agent）
   │  ① 摄取：df-memory 只读 df-app 库（专用只读账号 df_memory_reader）
   │  ② 调用：df 后端/前端/沙箱 agent → HTTP(df-memory /api/**) 或 MCP
   │        └ 带 Bearer API Token
   ▼
df-memory（独立部署，自有库 df_memory）
```

| 接入点 | 方式 |
|---|---|
| `chat_message_log`（摄取） | df-memory 只读 df-app 库（只读账号 + 增量游标），**df-app 零改动** |
| `work_item`/`work_artifact`/`work_phase` | 同上，只读映射 source_ref 与阶段事件 |
| 检索/写记忆（服务间） | df 后端调 `df-memory:/api/**`，带 API Token（D12） |
| 前端 | df-gateway 反向代理 `/memory/** → df-memory:/api/**` |
| 沙箱内 agent | 直连 df-memory 的 MCP server，或经 df-gateway 转发 |
| `workspace_memory` 表 | df-memory 不读它；数据迁移由 df-app 侧按需执行（一次性脚本） |

**独立性保证**：df-memory 对 df-app 的依赖**只有"读它的库"**（最小只读耦合）——df-app 不部署 df-memory 依赖、不 import 其代码、不改任何表/接口；df-memory 停机不影响 df-app 主链路（摄取重试，查询由调用方感知超时）。

## 9. 风险与开放问题

| 风险/开放问题 | 缓解/决策 |
|---|---|
| MySQL FULLTEXT 中文分词（ngram 最小粒度） | ngram_token_size=2 验证中文召回；不达标则 Phase 3 提前上向量 |
| 提取 LLM 选型与成本 | LLMProvider 可配置；默认轻量模型；CostGuard 熔断 |
| ADD-only 存储膨胀 | stale 归档 + 合并 Job；mem_fact 只存事实不存原文 |
| 图谱正则覆盖有限 | schema pack `extraVerbs` 可扩展；未覆盖走语义通道 |
| 经验"错误经验"复用 | eta_score + 适用边界 + 反例收集 + 人工 review（Phase 4 细） |
| **读 df-app 库的耦合**（表结构变更/大表查询） | 只读账号 + 只读副本 + 增量游标；df-app 表结构变更需通知 df-memory（开放问题：是否由 df-app 提供稳定视图/API 替代） |
| **独立服务鉴权** | API Token 按 workspace 签发 + 轮换 + admin 独立；MCP token 配置 |
| **独立调度多实例** | mem_job_state 行锁保证单实例；MVP 可先单实例部署 |
| 与 OpenViking 现有集成去留 | 默认自建（方案 A）；OpenViking 复用仅作向量后端备选（注意 AGPL） |
| `workspace_memory` 表数据迁移 | Phase 5 提供一次性迁移脚本，双写过渡 |
