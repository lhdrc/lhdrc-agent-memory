## 1. 项目定位

**一句话**：开源、单机、通用、本地部署的记忆模块——"agent 的 git + 知识库"。任何团队/个人 `clone` 即可运行，把多 source 的任务经验蒸馏、结晶、注入成一个可用的项目脑。

> **「git」在口号中的含义（D1/D18）**：产品体验像版本化知识仓（可 clone、可审计）；**实现上热路径以文件 + hash 索引为权威**，git 为可选批量账本，而非每次写入都调用 git。

**目标用户**：
- 直接用户：有 AI agent 工作流的个人/团队（Claude Code、Codex、OpenCode 等）；
- 集成方：像 df-app 这样的平台，通过**适配器**把 df-memory 接入自己的消息流。

**非目标**（YAGNI）：
- 不做分布式/多实例（**单机部署**，但**多租户是目标**——单实例内用 brain/source + 权限支持多团队，OpenViking 同款思路）；
- 不做对外商业托管（开源自托管，托管留给生态/未来）；
- 不做多模态记忆（纯文本优先，图像/工具轨迹后置）。

## 2. 设计原则（四项目精华）

| 原则 | 来源 | 含义 |
|---|---|---|
| 记忆 = 文件树 + 知识图谱 | GBrain + OpenViking | md 文件确定性寻址 + 零 LLM typed edges 关系推理 |
| 写入只增不覆盖（ADD-only，热路径） | Mem0 | **仅 L0 热路径**：提取单遍、只增 facts/节点；更新/归档由 D17 分层承载 |
| 写入时分层，读取时按需 | OpenViking | L0 摘要/L1 概览/L2 全文，检索按层注入省 token |
| 蒸馏"该用哪些信息" | OpenViking | LLM 两级去重判定 + memory_diff 审计，可回滚；**不删源文件**（D17） |
| 零 LLM 也能跑 | GBrain | 链接/意图/关系解析确定性正则；LLM 只用于富化 |
| 异步写入 + 可观测 | MemOS + OpenViking | 写入不阻塞，事件总线可观测 |
| 经验结晶为能力 | MemOS | 经验成熟 → SKILL.md → 技能体系 |
| 成本第一等公民 | GBrain | search mode + cost cap + 熔断器 |
| 隔离是架构保证 | GBrain | brain/source 双轴 + **路径前缀强制**（brain 级内容不得落根目录） |

## 4. 核心概念：brain/source 双轴（GBrain）

### 4.1 双轴心智模型

- **Brain = 访问边界**：一个记忆库实例默认一个 brain（开源默认：**一 brain 一仓**，推荐 `git init` 作账本）；同进程可挂载多个 brain（各仓独立或单仓多 `brains/{id}/` 前缀）。对应"一个项目脑"。
- **Source = 内容边界**：brain 内多个 source（session/issue/任务），slug 按 source 唯一。
- **落位铁律（D2）**：凡标注「brain 级」的内容，路径必须在 `brains/{brainId}/` 下；根目录只放实例内部状态，禁止放租户记忆。

```
memory-root/                              ← 记忆根（文件权威；推荐 git init 作账本；默认 = 单 brain）
├── .dfmemory/                            ← 实例内部状态（游标、索引 meta、pglite；非记忆内容；勿提交索引）
└── brains/{brainId}/
    ├── brain.yml                         ← brain 配置（id、name、描述、权限、可选 mounts）
    ├── sources/{sourceId}/
    │   ├── .dfmemory-source              ← source 路由配置
    │   ├── issues/{issueId}/             ← 默认 schema pack 形状（可换）
    │   │   ├── .meta.json
    │   │   ├── requirement.md
    │   │   ├── decisions/{n}-*.md
    │   │   └── lessons.md
    │   └── ...
    ├── entities/{slug}.md                ← 四原语：实体身份（含 redirect stub）
    ├── events/YYYY-MM/{slug}.jsonl       ← 四原语：事件账本
    ├── experiences/{id}.md               ← 跨 source 蒸馏层（brain 级）
    ├── skills/{name}/SKILL.md            ← 结晶技能（brain 级）
    └── contradictions.md                 ← dream 矛盾待裁决（brain 级）

# 可选（实例级，显式授权才可见）：
shared/skills/{name}/SKILL.md             ← 仅当 brain.yml mounts 声明时对该 brain 可见
```

> **注意目录形状**：上面的 `issues/{issueId}/`、`decisions/`、`lessons.md` 是**默认 schema pack（问题树模板）**，不是核心硬编码——见 §4.4。核心只认"source 下任意目录树 + frontmatter schema"。**df-app 适配器负责把 workspace/issue 映射到这里的 brain/source/路径**，df-app 形状不进核心。
>
> **多 brain 与 git**：开源默认一 brain 一仓，权限最简单。若单仓多 brain，隔离仍靠 `brains/{id}/` 前缀 + API scope；**git 历史对同仓成员可见**——不得伪装为强隔离。

### 4.2 source 解析链（7 层，GBrain 移植）

```
--source flag → env → .dfmemory-source dotfile → 路径前缀匹配
→ brain 级 sources.default → sole_non_default（单 source 自动路由）→ 字面 'default'
```

所有读侧 op 走 `sourceScope(ctx)` 强制 source 过滤（GBrain `sourceScopeOpts`），漏一线即跨 source 泄漏。brain 级路径（entities/experiences/skills/…）另走 `brainScope(ctx)`，禁止跨 `brains/{id}/` 前缀。

### 4.3 你的范式的映射

```
多个 source（任务/session/issue，粒度由适配器/schema pack 决定）各自沉淀
  → 蒸馏层（brains/{id}/experiences/）汇聚跨 source 可复用经验
  → 同一 brain 读 experiences/ + 检索本 brain 下各 source 的蒸馏物
  → 成熟经验 → 结晶 brains/{id}/skills/*/SKILL.md → 注入新任务
```

### 4.4 schema pack：核心通用，形状可配（重要）

**核心不硬编码任何路径语义**。目录结构、schema_type、merge_op、文件名模板全部由 **schema pack** 定义：

- **默认包 `problem-tree`**（问题树）：`issues/{id}/requirement|decisions|lessons` —— 面向"issue 驱动任务"用户，df-app 用的是它；
- **备选包示例** `topic-tree`（主题树）：`topics/{topic}/notes|facts`、`wiki-tree`（wiki 树）等——**后续按需贡献**；
- 新包 = 一个 YAML 声明（目录模板 + schema_type 清单 + 文件名模板 + merge_op），`memory schema use <pack>` 切换。

核心（引擎/检索/蒸馏/结晶）**只消费 frontmatter 里的 `schema_type` 与通用字段**，不感知具体路径语义。df-app 适配器只做"workspace→brain/source、issue→路径"的映射，不要求核心认识 issue。

### 4.5 四存储原语（跨 pack 通用的结构层）

> 目录树 + frontmatter 是**可读面**；下面四个原语是**结构面**（GBrain `GBRAIN_RECOMMENDED_SCHEMA.md:82-88` 模式），跨所有 schema pack 通用，是核心的一部分——用户改 schema pack 改不了它们。**落位一律在 `brains/{brainId}/` 下**（D2）。

| 原语 | 存储 | 作用 | 文件落位 |
|---|---|---|---|
| **Entity registry** | `entities/` + 索引 `entity_registry` | 实体身份：canonical ID + 全部别名 + 外部 ID；**合并 = 文件事务**（见下），索引仅投影 | `brains/{id}/entities/{slug}.md`（活实体或 redirect stub） |
| **Event ledger** | `events/` + 索引 `event_ledger` | 不可变事件流（meeting/email/capture/update/entity_merged）；有 provenance | `brains/{id}/events/YYYY-MM/{slug}.jsonl`（append-only） |
| **Fact store** | 节点 frontmatter `facts` 块 / `facts.md` + 索引 `facts` | 带 provenance 的结构化声明；矛盾 = 两个不同值的 fact | §5.1 facts 落位（仍在所属 source 节点下） |
| **Relationship graph** | 节点 frontmatter `links` + 索引 `links` | 类型化边（decided/works_on/references/...），支撑图查询 | §5.1 links |

**为什么四原语在文件层有落位**：文件权威原则要求**每个原语都能从文件重建**——`rebuild-index` 时四原语全部从 `entities/`（含 redirect）、`events/`、frontmatter `facts`/`links` 重扫，索引只是投影。

#### 4.5.1 Entity merge = 文件事务（D13，废止「只改 DB」）

> 原文「合并 = 数据库操作，不是文件合并」已废止。正确含义：**不是把两篇正文拼成一篇**，而是**身份关系必须落文件**，否则 `rebuild-index` 会复活分裂实体。

合并入单写者队列，原子步骤：

| 步骤 | 文件动作 | 说明 |
|---|---|---|
| 1. 选 canonical | 默认**人工确认**；规则选主仅作建议 | 身份误判是第一失败模式 |
| 2. 写活实体 | 合并 `aliases` / `external_ids`（及可选事实引用）到 `entities/{canonical}.md` | 权威身份只存在于文件 |
| 3. 写 redirect | loser → `status: merged` + `redirect: {canonical}`，**不物理删除** | 旧路径可解析；可回滚 |
| 4. 记事件 | `events/…` append `entity_merged`（from/to/by/at） | 审计依据 |
| 5. 投影索引 | `entity_registry`：alias→canonical；软删 loser 行 | 索引可丢，文件不可丢 |
| 6. git flush | **强制即时 commit**（D18 关键白名单） | 保证 `git revert` 能对准整次 merge |

**resolve**：索引快路径；miss 时扫 `entities/` + 跟随 redirect 链（depth≤2）。

**验收**：`merge → 删除索引 → rebuild-index` 仍解析到同一 canonical；在 `git.mode≠off` 时，`git revert` 该次 merge 的强制提交后身份分裂可恢复。

**身份去重心智**：两个 alias 指向同一 canonical ID——通过 redirect/aliases 文件表达，**禁止只 UPDATE 索引**（GBrain 承认分裂页是第一失败模式，`GBRAIN_RECOMMENDED_SCHEMA.md:158`）。

## 5. 存储设计（文件权威 + 检索索引）

### 5.1 权威存储：md 文件 + frontmatter

每个记忆节点 = 一个 md 文件，frontmatter 承载结构化 meta：

```markdown
---
title: 重试策略调整
schema_type: decision          # requirement/decision/lesson/experience/session/...
source: issues/1024            # 归属 source
path: issues/1024/decisions/1-重试策略调整
version: 1
status: active                 # active/archived/stale
created_by: agent:claude
created_at: 2026-08-02T10:00:00Z
tags: [payment, timeout]
aliases: [重试策略]
links:                          # 零 LLM 建边（frontmatter 声明 + 正文 wikilink）
  - { to: projects/payment, type: belongs_to, source: path }
  - { to: members/alice, type: mentions, source: mention }
facts:                          # 原子事实（文件即真相的一部分，同步进索引）
  - text: 重试策略由指数退避改为固定 3 次
    event_type: decision
    attributed_to: agent:claude
    at: 2026-08-02
  - text: 超时阈值由 2s 调整为 5s
    event_type: decision
    attributed_to: agent:claude
    at: 2026-08-02
---
## 摘要      (L1 overview 的源)
## 决策内容   (L2 全文)
指数退避改为固定 3 次退避，超时阈值 2s→5s。
[[decisions/2-超时阈值]] 相关。[[projects/payment]]
```

**frontmatter 即 schema**：`schema_type` 决定解析器/merge_op/文件名模板——**全部来自 schema pack（§4.4），核心只认通用字段**。示例里的 `issues/1024/decisions/1-重试策略调整` 是默认 `problem-tree` 包的形状，换成 `topic-tree` 包就是 `topics/foo/notes/...`，核心代码不用改。无迁移负担——加字段即演进。

**facts 落位（重要，防索引成为真相）**：原子事实写入**所属节点的 frontmatter `facts` 块**（上例），或聚合到每 source 一个 `facts.md`（源内事实统一管理，schema pack 决定用哪种）。**文件永远持有 facts 的权威副本，索引只是派生的同步**——`rebuild-index` 从文件重扫 facts，绝不丢事实。

### 5.2 检索索引（PGLite/pgvector）

| 索引表 | 内容 | 用途 |
|---|---|---|
| `pages` | 文件 meta + compiled_truth + synopsis + frontmatter | 页面级检索 |
| `chunks` | 正文分块 + embedding 列 | 向量检索 |
| `links` | typed edges（from/to/type/source） | 图谱遍历 |
| `facts` | 原子事实 + hash + event_type（**同步自文件 facts 块/facts.md**） | hot memory |
| `experiences` | 蒸馏经验（trigger/procedure/boundary） | 经验检索 |
| `skills` | 结晶技能（name/trigger/eta） | 技能检索 |
| `entity_registry` | 实体 canonical ID + 别名 + 外部 ID（同步自 `entities/`） | 身份去重 |
| `event_ledger` | 不可变事件流（同步自 `events/`） | 时间线/溯源 |
| `search_cache` | 查询缓存（knobs_hash） | 防污染缓存 |
| `change_log` | memory_diff 审计 | 审计/回滚 |

> **索引全部是派生数据**（可重建）；`pages/chunks/links/facts/experiences/skills/entity_registry/event_ledger` 都有文件权威落点，重建时从文件重扫，丢失=零容忍。

> 引擎双实现（GBrain parity 铁律）：**PGLiteEngine**（WASM Postgres，零配置默认）与 **PostgresEngine**（pgvector，大规模）。两个引擎锁步同一 schema；`index.engine: postgres` + `DF_MEMORY_DATABASE_URL`（P5.7）。失败不回退、不丢 md（D1）。见 [`specs/五期/P5.7-postgres-engine.md`](../specs/五期/P5.7-postgres-engine.md)、[`scripts/dev-postgres.md`](../scripts/dev-postgres.md)。

### 5.6 embedding 提供方（本地优先）

> 向量检索与去重/蒸馏的余弦快路径需要 embedding。**默认本地可离线**，不强制云 API：

| 档 | 提供方 | 场景 |
|---|---|---|
| 默认 | 本地小模型（如 bge-small-zh / all-MiniLM，经 Ollama / ONNX） | 离线、隐私、零成本 |
| 增强 | 云端 embedding API（OpenAI/text-embedding-3-small 等） | 语义质量优先 |
| 降级 | **无 embedding 也能跑**：向量通道退化为 BM25+图谱+路径 | 离线冷启动 |

`LLMProvider` 抽象了 embedding 与生成两类调用，embedding 提供方在 `memory.yml` 可切换，成本/延迟分别统计。**系统不依赖任何特定 embedding 服务**。

### 5.3 同步机制（文件 → 索引）

对齐 GBrain「类 git」心智（磁盘 = 工作区，索引 = 对象库，`content_hash` = blob）：

- 每次文件写入/软删后**增量同步**（进程内）：读文件 → 算 `content_hash` → 与索引行比较；**哈希相同则跳过**（幂等短路，不重分块/不重嵌）；
- hash 应对**语义稳定字段**归一化（至少剔除纯时间戳型 frontmatter，如 `captured_at`），避免「每次 capture 必变 hash」；
- 物理删除文件（若发生）→ 索引软删除/墓碑（`status`/`deleted_at` 语义）；MVP `forget` 默认只改 `status=archived`，文件仍在；
- 索引可**全量重建**（`rebuild-index`，从文件权威恢复）——索引是派生数据，丢了能重建，**文件是真相**。

### 5.4 git：可选批量账本（D18）

> **热路径不借 git 做文件管理。** 写事务的原子边界是「单写者锁 + 磁盘 md + 索引投影」，不是 `git commit`。
> git 提供审计 / clone 备份 / revert；未 flush 的 dirty 工作区**不是**丢权威，只是尚未进入版本史。

#### 5.4.1 类 git 三区对照（GBrain）

| git | df-memory | 说明 |
|-----|-----------|------|
| 工作区 | 磁盘 md 树（`brains/**`） | **权威**；用户/CLI 直接读写的原文 |
| 对象库 | PGLite `pages`/`chunks`/`entity_registry` 等 | 检索投影；可丢可重建 |
| blob 哈希 | `content_hash`（SHA-256） | 内容寻址、变更判定、幂等短路 |
| index 路径映射 | `path` / `source_id` 列 | 相对仓根路径 → 页面 |
| 提交历史 | `git log`（flush 后） | 可选账本，非热路径 |

#### 5.4.2 Flush 触发（默认 `mode: batch`）

| 触发 | 默认 | 行为 |
|---|---|---|
| 条数阈值 N | **20** 次成功写入累计 dirty | 一次 `git add` 约定路径 + 一个 commit |
| 时间阈值 T | **5 min** 且仍有 dirty | 同上 |
| 显式命令 | `memory sync --commit`（或 `memory commit`） | 有 dirty 才提交；无则 no-op |
| 进程退出 | CLI 正常退出 | best-effort flush（失败只 warn，不回滚已写文件） |
| 关键强制 | entity **merge**、`schema use`、**purge** | **立刻单独 commit**（便于 `git revert`） |
| 不触发 | hash 未变的 no-op、纯 query/read/`rebuild-index` | 禁止空 commit |

满足 **N ∨ T ∨ 显式 ∨ 退出 ∨ 关键** 任一即可；关键操作**插队**，不与普通 capture 混在同一 squash（除非同一次强制 flush 窗口内仅含该关键事务——实现上关键路径单独 commit）。

一次 flush = **一个 commit**，包含窗口内全部 dirty 路径；消息形如 `memory: flush 12 files` 或摘要 `+3 decision`；merge 单独：`memory: entity merge bob -> alice`。

**勿提交**：`.dfmemory/pglite/`、写锁、可丢的 index-meta（已由 `.gitignore` 约束）。

#### 5.4.3 配置（`memory.yml`）

```yaml
git:
  mode: batch              # off | batch | per_write（per_write 仅兼容/调试）
  auto_commit: true        # batch 下启用 N/T 自动 flush；off 时忽略
  commit_prefix: "memory:"
  batch_size: 20
  batch_interval_ms: 300000
  force_commit_on:
    - entity_merge
    - schema_use
    - purge
```

| `mode` | 含义 |
|---|---|
| `batch` | **MVP 默认**：热路径不 commit；按上表 flush |
| `off` | 永不自动 commit；仅显式命令（无 git / 极简环境） |
| `per_write` | 旧行为：每次成功写入都 commit（迁移/对照用） |

#### 5.4.4 风险边界（对用户说清）

- **丢索引** → `rebuild-index`，文件仍在。
- **丢未 commit 的工作区** → 丢数据（与任何未备份目录相同）；需要版本史就依赖 flush / 显式 sync / 关键强制 commit。
- **并发**：仍由单写者队列 + 文件锁串行；**不**用 git merge 解决多写者冲突。

## 6. 写入管线

### 6.0 四层写语义（D17，重要）

> 同时引入 Mem0 ADD-only、OpenViking merge/delete、dream archive 时，必须先排优先级——**谁能对源文件做什么**。

| 层 | 触发 | 允许写什么 | 禁止 |
|---|---|---|---|
| **L0 热路径** | `remember` / `capture` / REST | ADD-only：新建节点、append facts/links | merge 源节点、delete、改他人 source |
| **L1 蒸馏** | 异步 `refine` | **只写** `brains/{id}/experiences/`：skip \| create \| merge 经验投影 | 删/改 `sources/` 下源 md；「delete」= 归档旧经验版本 |
| **L2 维护** | dream cycle | 补 backlink、标 contradiction、orphan→`archived`、提 skill candidate | 无人工确认的硬删除；无确认的 entity merge |
| **L3 显式遗忘** | `memory_forget` / 人工 | `status=archived`（软删）+ event | 默认物理 `rm`；硬删需 `--purge` + owner |

**OpenViking 词表重映射**（D3 补丁）：

| 原判定 | 落层 | 文件效果 |
|---|---|---|
| candidate: skip | L1 | 不写经验；源事实保留 |
| candidate: create | L1 | 新建 `experiences/{id}.md` |
| item: merge | L1 | 合并进已有经验 md（经验层 merge_op） |
| item: delete | L1 | 旧经验 `status=superseded`；**源文件不动** |
| cosine duplicate | L0 快路径 | 跳过写入；零 LLM |
| dream orphan | L2 | 临时页 `archived`；硬删不在 dream 默认路径 |

**冲突裁决**：同 path 并发 → 单写者串行；事实矛盾 → 两 facts 并存并写入 `contradictions.md`，不自动删；注入优先级 Skill > 经验 > 源（源仅 L2 按需）。**memory_diff 覆盖 L0–L3 全部变更类**。

### 6.1 三种写入入口

| 入口 | 方式 | 场景 |
|---|---|---|
| **MCP 工具** | `memory_remember` | agent 主动决策写入（主通道，**L0**） |
| **CLI** | `memory capture/import` | 人/脚本写入（**L0**） |
| **REST** | `POST /api/memory` | 平台/适配器写入（**L0**） |

所有写入**统一进单写者串行化队列**（保证**文件 + 索引**顺序一致；git flush 按 D18 另算）。L0 入口经 `validateWrite()` 后**只允许 ADD-only / append**（D17）。

热路径步骤（每个 job）：

```
持锁 → mutation 写 md → content_hash 同步索引
  → 标记 dirty（记入待 flush 集合）
  → 若命中 force_commit_on 或 mode=per_write → 立即 git commit
  → 否则仅检查 N/T 是否触发 batch flush
  → 放锁
```

索引 hook 失败：文件已落盘则 **不回滚文件**，warn + 提示 `rebuild-index`（D1）。

### 6.2 写入格式即规格（重要）

> **"写库规定写入的格式"**：所有入口共享同一套**写入格式规范**（`WRITE_FORMAT.md`，随代码版本管理），约束"什么能写、怎么写、写哪"——AI 决策写入时按此格式，平台适配器按此格式，人按此格式，三处一致。

**写入格式规范涵盖**：

| 项 | 规定 |
|---|---|
| **frontmatter 必填** | `title`/`schema_type`/`path`/`source`/`created_by`/`created_at`/`status` |
| **schema_type 来源** | 必须来自当前 schema pack 声明的类型清单（pack 未声明 → 拒绝） |
| **facts 块格式** | `text`/`event_type`/`attributed_to`/`at`（见 §5.1 示例） |
| **links 格式** | `to`/`type`/`source`（`source` ∈ wikilink/markdown/mention/verb） |
| **正文约定** | 结构化 markdown（`## 摘要` + 主体），供 L0/L1 分层解析 |
| **merge_op** | 由 schema pack 声明（immutable/patch/append），决定更新语义 |
| **拒绝规则** | 敏感字段（可配 mask）、超长文本、非 UTF-8、路径越界（source scope 外）一律拒绝 |

**AI 决策写入的落点**：MCP `memory_remember` 内部调用 `validateWrite()`（按 WRITE_FORMAT 校验）→ 通过才入队。校验失败返回结构化错误，AI 可据此修正重试——**格式约束由系统强制，不靠 AI 自觉**。

### 6.3 提取（Mem0 ADD-only + GBrain 快路径，属 L0）

```
写入请求 → [快路径] 查相似现有事实（cosine≥0.95 → 跳过，零 LLM）
  → LLM 单遍提取（ADD-only，一次调用只做新增）
  → MD5 去重 → **写 facts 到文件（frontmatter facts 块 / facts.md）**
  → 写 md 文件 + content_hash 增量同步索引（热路径；不强制 git commit）
  → 按 D18 标记 dirty / 条件 flush
  → 异步分层（L0/L1）+ 零 LLM 建图 + 写 change_log
  → （可选）入队 L1 蒸馏，不在本步改/删源文件
```

**prompt 即规格**：提取 prompt 作为资源版本管理（Mem0 理念），约束输出格式（facts/entities/attributed_to/event_type）。

> **六期补丁（会话原文）**：Agent 交的是 transcript，不是「写入请求」。入口是 `compileSession`（单写队列一次 job），不是 `capture`。先归档 `.dfmemory/inbox/`，再 `complete()` 填 schema，最后 `captureWrite` 写 L0。LLM 失败标 inbox `failed`，不写 L0。会话路径默认 `compile.dedupe_cosine=0.95`。详见 [`specs/六期/`](../specs/六期/)。人手 `capture` 仍走本节写后 enrich（P5.1）。  
> **P6.6**：提取 prompt 按 `decision`/`lesson`/`note` 写成类型合同；`complete` 前可只读 prefetch 已有标题（ADD-only，不 patch）。不引入 OV 的 11 类记忆或 ReAct 工具循环。

### 6.4 蒸馏决策（OpenViking，D3 + D17，属 L1）

写入/摄取后的异步蒸馏管线——**只读写 `brains/{id}/experiences/`，禁止触碰 `sources/` 源文件**：

```
Candidate Memories（提取产物，只读引用源）
  → 向量预筛找相似 → 找到候选
  → LLM 两级去重判定（词表按 §6.0 重映射）：
      candidate 级：skip / create / none
      item 级：merge（并入现有经验）/ delete（= 旧经验 status=superseded）
  → 写或更新 brains/{id}/experiences/
  → memory_diff 审计（可回滚）
```

**关键**：决定"哪些信息进经验库"由 LLM 决策 + 审计，不做无脑 append；**OpenViking 的 delete ≠ 删源 md**。

### 6.5 分层生成（OpenViking L0/L1/L2）

- 文件写入后异步生成 `.abstract`（L0，~100 token）与 `.overview`（L1，~1-2k token）——存 frontmatter 或同级隐藏文件；
- 目录级也有 L0/L1（自底向上聚合）；
- 检索默认只注入 L0/L1，L2 按需读取。

### 6.6 零 LLM 建图（GBrain）

先 stripCodeBlocks；masked-ranges 防双发
inferLinkType 正则：decided/produced_by/works_on/references/mentions/belongs_to

## 7. 检索管线（GBrain 混合检索）

### 7.1 完整链路

```
Query（MCP find / CLI / REST / 注入）
  → 意图分类（零 LLM 正则）：task/experience/person/general
      （task = 任务型查询；"issue/工单/需求"等词由 schema pack 的意图词表映射到 task）
  → 可选 multi-query 扩写（tokenmax 档：轻量 LLM 生成 2-3 查询变体，各跑全栈后 RRF 合并）
  → 混合召回（并行）：
      ① 语义检索（向量，embedding 见 §5.6）
      ② BM25 关键词（PGLite FTS/ngram）
      ③ 图谱遍历（typed edges 关系查询）
      ④ 实体 boost（entity registry 匹配 → 提升关联记忆）
      ⑤ 关系查询 arm（relational recall：seed 实体 + 动词 → 图遍历）
  → RRF 融合（k=60）+ 归一化（Mem0 自适应 sigmoid）+ 调权
  → graph signals 调权（见 §7.4）
  → 目录级预筛（OpenViking：高分目录子树优先）
  → 可选 cross-encoder reranker（tokenmax 档，重排 top-N）
  → 分层加载（默认 L0/L1 snippet，命中才取 L2）
  → 排序去重（同 path 取最佳）→ 返回
```

### 7.2 融合公式（确定性基础版）

```
final = 0.55×rrf(keyword) + 0.30×rrf(graph) + 0.15×hotness
      （relation 意图时 graph 权重升 0.55）
threshold 前置：单一通道分 < floor 剔除
```

> **实现形态（P3.1）**：生产路径用五项线性融合 `w_kw×rrf(bm25)+w_sem×rrf(sem)+w_graph×rrf(graph)+w_title×title+w_entity×entity`（见 [`P3.1`](../specs/三期/P3.1-graph-signals.md) §7 冻结表）；**hotness 为 post-fusion 乘子**，不在 FusionWeights 内。上式 0.55/0.30/0.15 是语义通道不可用时的 **kw/graph/hotness 线性目标**（hotness 槽位 0.15 拆为 w_title+w_entity=0.15，hotness 仍后乘）。

> **语义通道完整形态**：`final = w1×rrf(keyword) + w2×rrf(graph) + w3×rrf(semantic) + w4×entity_boost + w5×hotness`，权重按 search mode 与意图动态分配（GBrain 思路）；上表是"语义通道不可用时的降级基础"。

### 7.3 关系查询 arm（GBrain relational recall）

```
parseRelationalQuery（确定性零 LLM）
  → 识别 seed + 动词 → 图遍历（depth≤2）→ hydrate 结果
fail-open：解析失败返回空 arm，不破坏热路径
```

### 7.4 graph signals 调权（GBrain）

| 信号 | 乘子 | 触发条件 |
|---|---|---|
| Adjacency within top-K | ~1.05× | ≥2 个 top-K 节点链入 = hub |
| Cross-source adjacency | ~1.10× | ≥2 个不同 source 链入 = 跨源 hub |
| Session diversification | ~0.95× | 同 source 前缀多个 top-K 节点只留最高分（MMR-lite） |

fail-open：任一信号不可用即跳过，不破坏热路径。

### 7.5 命名实体检索层（GBrain）

- **Per-page max-pool**：LIMIT 前按 path 折叠为每路径最佳 chunk，避免一个页面的弱 chunk 挤掉别页；
- **Title-phrase boost**：查询命中标题连续 token 串时 boost；
- **Alias hop**：`aliases:` frontmatter 投影进索引，查询时桥接零表面重合的同义词；
- **NER 类型链接**：`CEO of Acme` → 自动建 typed link（schema pack 提供正则）。

### 7.6 查询缓存与防污染（GBrain）

- `search_cache` 带 `knobs_hash`（search mode + 权重 + intent 参数折叠进 key），防跨配置污染；
- 升级/改配置后旧行不可达，一次性 miss spike 可接受。

### 7.7 检索可观测（Mem0 explain + OpenViking 轨迹）

- 每结果带 `evidence`（graph/semantic/keyword/alias/path）+ `score_details`（各通道分/分母/阈值）；
- 返回 `searched_directories`（下钻轨迹）+ `query_plan`；
- `observer` 命令看整体指标（total/zero-result/avg score/latency/evidence 分布）。

## 8. 维护循环（GBrain dream cycle）

### 8.1 九个阶段（GBrain `src/core/cycle.ts` 移植）

```
dream（夜间 cron / 手动）：
  ① lint --fix            路径/引用完整性、frontmatter 校验、schema lint（pack 规则）
  ② backlinks --fix       提及未反向链接的实体页 → 补 backlink（Iron Law，见下）
  ③ sync                  文件 → 索引增量同步（补上次未完成的）
  ④ synthesize            会话/消息 → 页面（transcripts 归位）
  ⑤ extract               补跑事实提取（未提取的消息）
  ⑥ patterns              跨会话主题归纳（pattern 页）
  ⑦ recompute_weight      hotness/emotional_weight 重算
  ⑧ embed --stale         补齐未向量化的 chunks/entities
  ⑨ orphans               清理孤儿（无入链的临时页 → archive）

+ 蒸馏补跑（未蒸馏的经验 → brains/{id}/experiences/；属 L1，不删源）
+ 矛盾检测（两个 decision/事实冲突 → 标记待人工裁决；facts 并存）
+ 结晶检查（成熟经验 → 候选 skill；写入 brains/{id}/skills/）
```

> dream 默认路径属 **L2**（D17）：只软归档与标记，**无人工确认不做硬删除 / entity merge**。

### 8.2 关键维护规则

- **Iron Law back-link**（GBrain `skills/conventions/quality.md:23-30`）：提到有实体页的人/公司必须 back-link 到提及页；每条事实带 `[Source: ...]` 内联引用。
- **不变量**：文件权威永远成立——维护循环只改文件/重建索引，**绝不只改索引**（否则重建丢数据）。
- **幂等**：内容 hash 未变跳过；崩溃恢复以**磁盘文件**为准，重启后索引与文件对齐（`rebuild-index` 兜底）；git 仅恢复「已 flush」的历史版本。

### 8.3 矛盾检测（GBrain `facts/classify.ts`）

- **快路径**：候选事实 cosine ≥ 0.95 → 判 DUPLICATE（零 LLM，最便宜的去重）；
- **LLM 分类**：duplicate / supersede / independent；
- **降级**：LLM 失败时 cosine ≥ 0.92 → DUPLICATE，否则 INSERT（GBrain D12 模式）；
- 结果写 `brains/{id}/contradictions.md`，供 dream 尾声人工 review。

## 9. 结晶层（MemOS Reflect2Evolve 简化，D5）

### 9.1 流程

```
经验成熟判定：eta_score ≥ 阈值 且 support（被复用次数）≥ 2 且无反例
  → 提炼：把多条同 trigger 经验 LLM 归纳为通用 procedure
  → 状态机：candidate → active → archived
      candidate：初版，待验证
      active：真实任务验证成功
      archived：被反例否定 / 不再适用
  → 反例收集：skill 被用但失败 → counter_examples → rework 或 archive
  → 打包：生成 SKILL.md（trigger/procedure/boundary/verification/反例）
  → 注册进技能体系（`brains/{id}/skills/` 目录；可选 sync 到 shared/ 需显式授权）
```

### 9.2 产出物：SKILL.md

```markdown
---
name: payment-timeout-fix
trigger: "支付网关超时/重试相关任务"
eta: 0.8
support: 3
status: active
source_trajectory_ids: [task#101, task#202]
counter_examples: []
---
## Procedure
1. 检查重试策略配置（指数退避→固定次数）
2. 确认超时阈值（2s→5s 需业务确认）
3. 验证 500 错误码场景
## Boundary
适用于支付类同步调用；不适用于异步队列场景
## Verification
跑 `make test-payment-timeout` 验证
```

### 9.3 与 df-app 技能体系对接（适配器能力）

- df-memory 的 SKILL.md 与 df-app 现有 skill 规范**同构**（SKILL.md + scripts）；
- df-app 适配器把结晶技能同步进其 mcphub 分发通道（可选插件）。

## 10. 注入机制（混合式，D6）

```
任务启动（系统注入，被动）：
  检索 project 级经验 top-3 + 命中 skill → 注入初始上下文/SYSTEM_PROMPT
运行时（agent 主动）：
  MCP memory_find/read → 随时查
  遇到新情况 → memory_remember → 主动写
注入优先级：已结晶 Skill > 成熟经验 > 原始任务记忆（不直接注入原始记忆）
```

### 10.1 agent 适配器（注入的落地通道）

> "启动注入"需要每个 agent harness 的具体接入点。**agent 适配器**（对标 df-app 摄取适配器，反向：这是"记忆→agent"）逐 harness 定义：

| Agent | 接入方式 | 注入点 |
|---|---|---|
| **Claude Code** | CLAUDE.md + hooks（`PostToolUse`/`SessionStart`） | SessionStart hook 调 `memory_find` → 注入上下文；CLAUDE.md 声明记忆协议 |
| **Codex** | AGENTS.md + 前置 prompt 拼接 | 启动脚本把 `memory_find` 结果写入初始消息 |
| **OpenCode** | opencode.json（instructions + command） | instructions 指向记忆；/memory 命令触发查询 |
| **OpenClaw / Hermes** | 插件（recall-trace + session lifecycle） | 插件注入召回 + 自动 commit（对标 OpenViking 插件模式） |
| **df-app 沙箱 agent** | 适配器：沙箱内注入 MCP 连接 + 启动上下文 | 复用 df-app 现有 ACP/MCP 通道 |

**通用约定**：每个适配器做两件事——(1) 任务启动注入召回；(2) 任务结束提交会话记忆（自动或经 agent 确认）。MCP 工具本身是跨 harness 的统一运行时通道，适配器只在"何时调用"上差异。

## 11. 多租户与权限（单机多租户，D8）

> 单机部署但**多租户是目标**：一个实例服务多个 brain（团队），brain 之间隔离，brain 内 source 隔离。

### 11.1 三级隔离模型

| 层 | 单位 | 隔离 |
|---|---|---|
| **实例** | 单机进程 | 全部 brain 共用 |
| **brain** | 团队/项目 | 完全隔离（目录 + 权限 + 索引 scope） |
| **source** | 任务/session/issue | brain 内隔离（source scope 强制） |

### 11.2 权限模型

| 角色 | 范围 | 能力 |
|---|---|---|
| `owner` | brain | 全部（含删除/权限管理） |
| `admin` | 实例 | 全部 brain + 系统配置 |
| `member` | brain | 读写该 brain 的 source（受 source scope 约束） |
| `reader` | brain | 只读 |

- **身份**：`memory.yml` 里配置用户 + API token（按 brain 签发，可轮换）；
- **source 访问**：所有读侧 op 强制 `sourceScope(ctx)`（§4.2），成员只能读写自己被授权的 source 子集；
- **agent 身份**：MCP 请求带 `agent_id`，agent 只能读写自己参与的 source（对标 df-app session ownership 语义）；
- **fail-closed**：未显式授权即拒绝（GBrain `OperationContext.remote` 纪律）。

### 11.3 权限测试

- **fuzz 隔离**：跨 brain / 跨 source 读全路径（node/fact/edge/experience/skill/admin API）断言零泄漏；
- 该测试进 CI（§17），每次权限改动必跑。

### 12.1 MCP 工具（agent 主通道）

| 工具 | 功能 | 内部 |
|---|---|---|
| `memory_find` | 检索（混合） | 检索管线 |
| `memory_read` | 读节点（L0/L1/L2 按需） | 读文件/索引 |
| `memory_grep` | 关键词搜 | keyword |
| `memory_list` | 浏览目录树 | 文件树 |
| `memory_remember` | 写记忆（主动） | 写队列 |
| `memory_forget` | 软归档（L3：`status=archived`）；硬删需 `--purge` + owner | 写队列 |
| `memory_refine` | 手动触发蒸馏/结晶 | 蒸馏层 |

### 12.2 CLI（人/脚本）

`memory capture / import / query / think / dream / graph-query / tree / find / schema / skill / eval`（GBrain CLI 面精简）。

### 12.3 REST（平台/适配器）

`GET /health` · `POST /api/memory` · `POST /api/retrieve` · `GET /api/memory/{path}` · `GET /api/tree` · `POST /api/refine` · `POST /api/skill/{name}` · admin 面（observer/costs/changes）。

## 13. 技术栈：双方案

### 方案 A：TypeScript / Bun（推荐）

| 项 | 选型 |
|---|---|
| 运行时 | Bun（单文件二进制，`npx`/`bunx` 一键跑，本地部署友好） |
| 权威存储 | md 文件 + frontmatter（文件权威）；git 可选批量账本（D18） |
| 检索索引 | **PGLite**（WASM Postgres，零配置）→ PostgresEngine（pgvector，大库） |
| 图谱/检索 | 自研检索层（RRF/hybrid/graph，GBrain 移植思路） |
| MCP | 官方 MCP TS SDK |
| CLI | Bun 原生 + commands 目录 |
| 发布 | npm，全球分发；`memory init && memory serve` 即可用 |
| 生态 | 与 GBrain/agent 生态同栈，社区可复用 |

**理由**：开源通用单机模块，TS/Bun 是 agent 生态母语，PGLite 原生支持（GBrain 正是这条路，且已证明可行），分发最轻。

### 方案 B：Java 17（备选）

| 项 | 选型 |
|---|---|
| 运行时 | JVM + Spring Boot（需打包 jar） |
| 权威存储 | md 文件 + frontmatter（文件权威）；git/JGit 可选批量账本（D18） |
| 检索索引 | SQLite（本地）+ 可选 Postgres/pgvector；向量可接 Qdrant 本地 |
| MCP | Java MCP SDK |
| CLI | Picocli |
| 发布 | jar + 安装脚本（分发重） |

**理由**：与 df-app 技能栈一致，若 df-app 团队希望参与核心开发可选。

**决策建议**：**主推 A（TS/Bun）**，B 作为"若团队必须 Java 维护"的备选。两者接口契约（§14）完全一致，可互相移植。

## 13. 接口契约（核心抽象）

> 双方案共享同一组接口语义，TS/Java 各实现。以下为 TS 签名（Java 同名对应）。

```ts
// 节点（文件树）
interface MemoryNodeService {
  createNode(req: CreateNodeRequest): Promise<string>;      // 返回 path
  getNode(path: string, opts?: {loadDetail?: boolean}): Promise<NodeDTO>;
  listChildren(path: string, opts?: {depth?: number}): Promise<NodeSummaryDTO[]>;
  updateNode(path: string, req: UpdateNodeRequest): Promise<NodeDTO>;
  archiveNode(path: string): Promise<void>;
}

// 检索
interface MemoryRetrieveService {
  retrieve(req: RetrieveRequest): Promise<RetrieveResponse>;
}

// 蒸馏/结晶（L1/结晶；不触 sources/ 源文件，D17）
interface ExperienceService {
  refine(sourceId: string): Promise<string>;                 // 蒸馏，返回 expId；只写 experiences/
  queryExperiences(triggerText: string, limit?: number): Promise<ExperienceDTO[]>;
}
interface SkillService {
  crystallize(expId: string): Promise<string>;               // 结晶，返回 skillPath（brains/{id}/skills/）
  listSkills(opts?: {status?: SkillStatus}): Promise<SkillDTO[]>;
  onSkillOutcome(skillName: string, success: boolean): Promise<void>;  // eta/support/reward
}

// LLM 抽象（可插拔）
interface LLMProvider {
  extractFacts(ctx: ExtractContext): Promise<ExtractResult>;
  judgeDistill(existing: string[], candidate: string): Promise<DistillDecision>;
  generateAbstract(content: string): Promise<string>;
  generateOverview(children: string[]): Promise<string>;
  refineExperience(ctx: ExperienceContext): Promise<ExperienceResult>;
  // embedding（可本地/云端/关闭，§5.6）
  embed(texts: string[]): Promise<number[][]>;
}

// 写入格式校验（D14）
interface WriteValidator {
  validate(req: CreateNodeRequest): Promise<ValidationResult>;  // 按 WRITE_FORMAT 校验，失败返回结构化错误
}

// 实体身份（四原语，D13）—— merge 必须落文件，禁止只改索引
interface EntityRegistry {
  resolve(alias: string): Promise<Entity>;        // 别名 → canonical（索引快路径；miss 跟 redirect）
  merge(entityIds: string[]): Promise<void>;       // 文件事务：canonical + redirect + entity_merged 事件 → 再投影
  linkFacts(entityId: string, factIds: string[]): Promise<void>;
}

// 事件账本（四原语，append-only）
interface EventLedger {
  append(event: MemoryEvent): Promise<void>;       // 不可变，带 provenance
  query(source: string, from?: Date): Promise<MemoryEvent[]>;
}

// 多租户权限（D15）
interface AccessControl {
  authorize(req: AuthedRequest): Promise<AuthContext>;  // token → 角色 + brain/source scope；fail-closed
}
```

DTO（`RetrieveRequest/Response`、`NodeDTO`、`ExperienceDTO`、`SkillDTO`、`DistillDecision`、`Entity`、`MemoryEvent`、`AuthContext`、`ValidationResult`）语义与 `07` §3.4 对齐并扩展。

## 18. 落地路线图（CLI 优先：MVP / 二期 / 三期 / 五期 / 六期 / 七期；四期为补充期）

> **分期原则**：架构语义（含 D2/D13/D17）全量保留；**实现顺序裁剪**。MVP 只交付 CLI、零 LLM 默认可跑；二期补检索+蒸馏；三期补图谱/结晶/多租户；**五期补架构剩余能力**；**六期补会话摄入**；**七期补 LLM 真路径与图**；**MCP/REST 为四期补充期（后置）**。Java 不进交付。

### 18.1 决策锁定

| 项 | MVP | 二期 | 三期 | 四期 |
|---|---|---|---|---|
| 产品面 | **仅 CLI** | CLI（query/refine） | CLI（graph/skill/dream/brain） | MCP + REST + 适配器 |
| 运行面 | 单 brain、单仓 | 同左 | 多 brain / 多租户 | 挂载三期鉴权 |
| 成本面 | 零 LLM 默认可跑 | 可选 LLM 蒸馏 + kill-switch | cost cap / observer | 同左 |
| 检索面 | BM25 + 路径/标题 | 向量 + RRF + 中文门禁 | + 图谱 + signals | 经工具面暴露 |
| P0 语义 | D1/D2/D13/D17/D18 **遵守** | experiences 管线（D17 L1） | skills/dream；隔离 fuzz | agent 不直读文件（D7） |

### 18.2 MVP（CLI 可 clone 即用）

**一句话**：人/脚本用 CLI 往一个 brain 里 **ADD-only 写入** md，能 **查回来**，索引丢了能 **rebuild**。

| 纳入 | 不纳入（推后续期） |
|---|---|
| `memory init`：brain 树 +（推荐）git init + `.dfmemory` + 默认 `problem-tree` pack | MCP / REST / harness（**四期**） |
| `capture` / `import` + `WRITE_FORMAT` + 单写者队列 + **索引 hash 同步**；git 按 D18 **batch flush**（含 `sync --commit`） | LLM 提取 / 蒸馏（**二期**）；结晶（**三期**） |
| `query`（BM25+path/title）+ `tree` + `read` | 向量、RRF（**二期**）；graph signals、关系 arm（**三期**） |
| `forget` 软归档（D17 L3 默认）；`--purge` 接口预留可不实现 | 硬删产品化 |
| Entity：`create` / `resolve`；**merge 文件事务**（CLI `entity merge`，默认需 `--confirm`） | Event ledger 全量产品化、facts 矛盾自动分类 |
| 索引最小集：`pages` / `chunks`（向量列可空）/ `entity_registry` + `rebuild-index` | `experiences`（**二期**）/ `skills`（**三期**）；目录可预建空壳 |
| 单 brain；本地 `memory.yml` | 多租户 RBAC、dream、cost（**三期**） |
| 测试：写→同步→查；rebuild 一致；merge→rebuild 身份仍在；路径不越界 | 检索门禁（二期）、隔离 fuzz（三期） |

**MVP CLI 命令面（冻结）**：

`init` · `capture` · `import` · `query` · `read` · `tree` · `forget` · `entity`（list/resolve/merge）· `rebuild-index` · `schema use`（仅默认 pack）

**MVP 验收口令**：

```bash
memory init ./demo && memory capture --title "..." --type decision --body "..."
memory query "重试" && memory rebuild-index && memory query "重试"  # 结果语义一致
memory entity merge a b --confirm && memory rebuild-index          # resolve 仍指向 canonical
```

> **诚实边界**：MVP 是「可写可查的本地记忆仓」，不是「会自己蒸馏的 agent 脑」。记忆质量靠人/上游按 `WRITE_FORMAT` 写对；中文召回靠标题/路径 + BM25 ngram 扛住，语义检索进 **P2.1a**。

## 20. 风险与开放问题

| 风险 | 缓解/决策 |
|---|---|
| 单机规模上限 | 明确边界（团队级几千任务节点）；索引可换 PostgresEngine 扩；不承诺分布式 |
| 蒸馏有效性 | mini-bench 实证；LLM 决策 + 审计回滚；低置信降级人工 review |
| 结晶把坏模式固化 | 反例收集 + 状态机退化 + 人工 gate（candidate→active 需验证） |
| PGLite 中文检索 | MVP 用标题/路径 + BM25 ngram 扛住；P2.1a 设硬门禁，不达标则本地 embedding 承担语义召回 |
| 单写者队列跨进程 | 文件锁 / 进程内单写者；CLI/REST/MCP 并发写由队列串行化 |
| git 提交频率（**已关闭 → D18**） | 默认 batch：N=20 ∨ T=5min ∨ 退出 flush ∨ 显式 sync；merge/schema/purge 强制即时 commit；`mode: off\|per_write` 可切 |
| 实体合并误判 | merge 默认人工确认；redirect + event 可追溯；强制 commit 后 `git revert` 可回滚；禁止只改索引 |
| 多租户权限泄漏 | fail-closed + brain/source 路径强制 + 隔离 fuzz 进 CI；experiences/skills 不得落根目录 |
| agent 适配器覆盖不全 | 核心只依赖 MCP 统一通道；harness 特定注入作为增量插件 |
| 与 df-app 现有 OpenViking 集成 | 适配器替换；df-app 侧可裁剪；蒸馏 delete 语义按 D17 重映射 |
| 双技术栈维护成本 | 接口契约一致；主推 TS，Java 备选不并行演进 |
| 评测体系未建 | **已关闭（P5.6）**：hermetic mini/distill/report + LoCoMo fixture；全量 fetch --allow-net |
| 写语义冲突（已关闭） | D17 四层模型：热路径 ADD-only；蒸馏不删源；dream 软归档；forget 默认软删 |
