# Spec P8.3 — Skill 查找与按需注入

| 字段 | 值 |
|---|---|
| ID | P8.3 |
| 状态 | done（本仓 P83-01–03 绿；插件 memory_skill + 注入 A 通道 + P83-10–17 绿） |
| 依赖 | P3.2 状态机与 `listSkills` / `activateSkill`；P7.2 自动只到 candidate；P8.1 注入通道调研；P8.2 默认可剥离 skill |
| 对应架构 | 08 §8–§9；TODO #7（**纠正用词**：不是独立抽取管线） |
| 仓库 | 本仓：`listSkills` 增字段；插件仓：工具 + 注入 |

> skill 是**规则层**（可注入的行为约束），不是知识检索的又一种 hit。  
> 结晶路径不变：experience 成熟 → `SKILL.md` `candidate` → 人工 `activate`。  
> 本期做：**查找面独立**、**命中后注入**、默认 `memory_query` 不混 skill。

## 1. 目标

1. 默认知识检索可剥离 skill（P8.2 `excludeSchemaTypes: ["skill"]` 在插件生效）。显式 `type=skill` 仍可用。  
2. 独立工具：`memory_skill`（list / find / read 三个 action，或三个工具名，见 §4）。返回 name、status、trigger、路径。  
3. 模型（或门控）需要规则时：find → 命中 → **注入** trigger + procedure 摘要（默认不是整份 SKILL.md）。  
4. 注入落点按 §3 调研锁定**一条**，写入插件 README。  
5. shared skills 走既有 `filterSharedSkillsHits` / `listVisibleSharedSkills`；不可见的不注入、不出现在 list。  
6. 不自动 `activate`；candidate 默认可被 find 到，但 section 写明「candidate 未激活，采用需谨慎」。

## 2. 非目标

- 会话 `compileSession` 新增 `type: skill` 或直接写 `SKILL.md`  
- 自动 `skill activate`  
- 改成熟公式（仍 `eta_score >= 0.7 && support >= 2 && counter_examples.length == 0`）  
- 在 core 实现 DSH 专有 inject  
- 把全部 active skill 每轮塞进 system prompt（防膨胀）  
- 替换 DSH 官方 `dsh-skill` 包；只允许**复用其注入通道**或完全自管

## 3. 调研门槛（注入落点，实现注入前必选一）

查 DSH 文档 / `dsh-skill` / `dsh-skill-filesystem`：

| 选项 | 何时选 | 行为 |
|---|---|---|
| **A. 宿主 skill 通道** | 官方有稳定 `ctx.skills.register` / 等价 inject API | find 命中后登记为本次会话 skill；卸载时摘掉 |
| **B. systemPrompt section** | 无 A，但 `ctx.systemPrompt` 可动态补一段 | 写入 `df-memory-skill` section（`complete: false`）；新会话或卸载清除 |
| **C. 仅工具返回** | A/B 都不可靠 | `memory_skill find` 返回正文摘要，由模型自行遵守；section 说明「命中即当规则」 |

**锁定（已选 A）**：`@deepseek-ai/dsh-skill`（DSH 宿主 0.1.0-rc）提供稳定 `ctx.skills.register(SkillRegistration): () => void`（SkillRegistry，返回 disposer 卸载摘除；同名 runtime 注入 first-wins 天然幂等）。插件以 `ctx.get("skills")` 访问（skills 不在 inject 列表，同 llm 坑）。**只实现 A**，禁止 A+B 双注入同一 skill（重复膨胀）。  
P8.1 的知识 inject（query hits，pre-step waterfall / `agent.inject`）与本 Spec 的规则 inject **通道不同、内容分开**（知识走消息注入，规则走 skills 注册）。

调研结论已写入 `dsh-df-memory` README「P8.3 Skill 注入」节。

## 4. 技术方案

### 4.1 core：`listSkills` 增字段

现返回 `{ name, path, status, title }`。本期增加（缺则空串/默认）：

```ts
{
  name: string;
  path: string;
  status: string;
  title: string;
  trigger: string;
  eta_score: number;
  support: number;
}
```

不把 `procedure` 全文放进 list（防 list 本身膨胀）。`find` 需要匹配时：对 `title`/`trigger`/`name` 做大小写不敏感子串；可选再对 procedure 做一次（命中才读文件）。

建议新函数（本仓）：

```ts
findSkills(repoRoot, brainId, query: string, opts?: {
  status?: SkillStatus | "any";
  limit?: number;
}): Promise<SkillListItem[]>
```

`query` 空 → 等同 `listSkills`（仍受 status 过滤）。默认 `status` 对插件 find = `"any"`，list 默认只 `active`（参数可改）。

鉴权：路径必须在当前 brain（或 shared mount 且 `listVisibleSharedSkills` 允许）。

### 4.2 插件工具

一个工具 `memory_skill`（减少工具表膨胀）：

| 参数 | 类型 | 含义 |
|---|---|---|
| `action` | `list` \| `find` \| `read` \| `inject` | 必填 |
| `query` | string | find 必填 |
| `name` | string | read / inject 必填 |
| `status` | `active` \| `candidate` \| `archived` \| `any` | list/find 可选 |
| `inject` | boolean | find 命中 top-1 时是否立刻注入；默认 false |
| `limit` | number | find 返回上限（默认 10） |

**已实现**：单一工具 `memory_skill`（四合一 action），见插件 `src/skills.ts`。

`read`：读 `SKILL.md` 全文（经 `readNode` 或直接读文件 + 路径校验），等同「模型明确要全文」。

`inject`：

1. 按 name 读 skill；不存在 → `E_NOT_FOUND`  
2. 不可见（shared ACL）→ `E_NOT_FOUND`（不泄露存在性）  
3. 组装注入体（§4.3）  
4. 走 §3 选定通道（**A：`ctx.skills.register`**，skill name 需宿主 kebab-case；不合法 → `E_USAGE`）  
5. 返回 `{ injected: true, name, channel: "host", chars: N, injected_names: [...] }`

### 4.3 注入粒度与预算

默认注入体：

```
## Skill: {name} ({status})
Trigger: {trigger}
Procedure:
{procedure 截断至 skillInjectMaxChars}
```

| 配置 | 默认 | 含义 |
|---|---|---|
| `skillInjectMaxChars` | 2000 | 单 skill 注入上限 |
| `skillInjectMaxCount` | 3 | 同一会话累计注入个数；超出 → 拒绝并提示先 `read` 或换 name |

`boundary` / `verification` 默认不注入；`read` 才给全文。  
超预算：`E_USAGE` + message 说明已注入列表，不静默截到不可读。

同一 `name` 重复 inject：幂等（不叠加第二份）。

### 4.4 与 activate 的关系

- `activateSkill` **不**在本期做成「activate 后自动每轮注入」。  
- 注入是**按需、按会话**的。  
- 以后若要「active 自动注入」，另开 Spec；本期 section 只说：常用规则用 find+inject。

### 4.5 默认 query 剥离

依赖 P8.2。若 P8.2 未合并：插件侧对 hits `path` 含 `/skills/` 的项移到可选字段 `skills_stripped`（不进主 hits）。P8.2 合并后改走 `excludeSchemaTypes`。
