# Spec P8.4 — 提取粒度（note 合并同类）

| 字段 | 值 |
|---|---|
| ID | P8.4 |
| 状态 | done |
| 依赖 | P6.6 提取合同（**不得破坏**） |
| 对应架构 | 08 §6.3 prompt 即规格；TODO #4 |
| 仓库 | 本仓 `packages/core/resources/session-extract-v1.md` + 测例 |

> 实测：清单式 / 长 body 一次 remember 会拆出 5–7 条小 note。  
> 根因在提取说明书的 **Split** 段（「独立事实 → 多条」），不是插件输入格式能单独修的。  
> 插件侧预处理列为**非目标**。先用真实对话样本确认碎的程度，再改合同。

## 1. 目标

1. `session-extract-v1.md` 增加**条目粒度**条款：同类、同一主题、同一清单下的稳定事实应合并为 **一条** note（或一条 decision），而不是逐条拆文件。  
2. **独立**决策 / 教训仍拆条（P6.6 §4.1「独立结论拆开」保留）。  
3. 单条 note 须有最小信息量：禁止「只有一个名词 / 半句清单项」的空心 note。  
4. P6.6 已锁合同保持：三类型、禁 path/wikilink/frontmatter、`source_turns`、prefetch 已有标题、一次 JSON 修复、`{ "items": [] }` 合法。  
5. 验收同时覆盖：**结构化清单 body** 与 **真实对话样本**（至少 1 份）。清单样本 note 数显著下降且信息不丢；对话样本不得比改前明显漏决策。

## 2. 非目标

- 增加 schema 类型  
- 插件 remember 前聚合/裁剪 body  
- L0 upsert / 改 ADD-only  
- 改 `complete()` 次数或 ReAct  
- 把说明书搬进 schema pack YAML  
- 用启发式在 `complete` 之后再合并 items（合并必须是模型按合同一次产出；后处理合并易丢 `source_turns`）

## 3. 先测再改（强制顺序）

1. **冻结基线**：用现网 prompt 对两份 fixture 跑 mock **或** 录一版真实 `complete` 输出（提交的是 fixture 期望，不是 Key）。  
2. Fixture A：`packages/core/tests/fixtures/extract-list-body.md`（或 jsonl）——模仿「结构化清单式 remember」。  
3. Fixture B：一段真实多轮对话（从 `test4humancli` 或 inbox 脱敏），含 1 个明确 decision + 若干闲聊。  
4. 改 prompt 后：A 的 item 数下降（见 §6）；B 的 decision 仍在且闲聊不进 note。

未完成步骤 1–3 不得改生产 `session-extract-v1.md`。

## 4. 合同增量（写入 session-extract-v1.md）

在现有 `## Split (atomic items)` 之后（或改写该节）增加 **Granularity** 节，语义必须包含：

| 做 | 不做 |
|---|---|
| 同一主题的清单（步骤、文件列表、配置项罗列）合成 **一条** note，body 内可用短列表 | 把清单每一行变成一条 note |
| 一条 note 至少回答「以后凭什么想起这件事」（对象 + 稳定事实） | 标题或 body 只有单词 / 编号项 |
| 两个互不依赖的决策仍两条 decision | 用一条「项目讨论」桶装多个决策（P6.6 已禁） |
| 用户一句「记住这些」+ 清单 → 优先 **一条** note | 为凑条数拆文件 |

保留 P6.6 对照：

```
Bad: one item titled “发布调整” covering delay + new owner.
Good: two items — “上线延期到6月3日” and “清单负责人改为 Lina”.
```

并追加对照（本期）：

```
Bad: five notes from one checklist (file1, file2, file3, …).
Good: one note “初始化检查清单” whose body lists the items.
```

Few-shot 若与新条款冲突，改 few-shot，不另开第二份 prompt。

P63-11 仍要满足：文本含 `"items"`、`{ "items": [] }`、`Few-shot`、`decision`。
