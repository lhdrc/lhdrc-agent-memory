## 1. 目标

1. 单进程多 brain（各 `brains/{id}/`；默认仍可一仓一 brain）  
2. 角色：owner / admin / member / reader  
3. API token 签发与校验；fail-closed  
4. 所有读/写路径强制 `brainScope` + `sourceScope`（**先服务 CLI**；P4.1 复用同一 `AccessControl`）  
5. CI **隔离 fuzz**：跨 brain/source 零泄漏  
6. 评测目录脚手架 `evals/`（公开基准适配可先 stub）  

## 2. 非目标

- 分布式多实例  
- 完整 OAuth 2.1（可留接口；本 Spec 用 token）  
- 实现 MCP/REST 服务本身（**P4.1**）；本 Spec 只定义鉴权内核与 CLI 多 brain  

## 3. 身份模型

`memory.yml`：

```yaml
auth:
  users:
    - id: alice
      role: owner          # 实例级 admin 另标
      brains:
        default: { role: owner, sources: ["*"] }
        team-b: { role: member, sources: ["app", "ops"] }
  tokens:
    - id: tok_1
      user: alice
      hash: "sha256:..."   # 只存 hash
      brain: default       # 可选收窄
```

`AccessControl.authorize`：

- 无 token（本地 CLI 默认）→ **trusted local** 角色 owner（仅限 loopback/CLI）  
- 将来 MCP/REST（P4.1）无 token → **拒绝** `E_AUTH`（本 Spec 用单元/夹具覆盖该分支即可）  
- token 无效 → 拒绝  
- 操作 path 不在授权 brain/source → `E_PATH_ESCAPE` / `E_FORBIDDEN`  

新增错误码：`E_AUTH`、`E_FORBIDDEN`。

## 4. 多 brain 操作

```
memory brain create <id>
memory brain list
memory --brain <id> query ...
```

索引：所有表带 `brain_id`；query 必带当前 brain。  
**禁止** 默认跨 brain 联合检索。

shared/skills：仅当 `brain.yml`：

```yaml
mounts:
  - type: shared_skills
    path: shared/skills
```

未 mount → 检索不可见。

## 5. 隔离 Fuzz

`packages/core/tests/isolation_fuzz.test.ts`：

1. 创建 brain A/B，各写入独特 secret 字符串到 md  
2. 用仅授权 A 的 token 调用：read/query/list/grep/entity/experience/skill/admin（及将来 find 等价 CLI）  
3. 断言响应 JSON/文本 **不含** B 的 secret  
4. 直接传 B 的 path → `E_FORBIDDEN` 或 `E_NOT_FOUND`（不得返回内容）  
5. 随机 100 次 path 变异（`../`、绝对路径、URL encode）  

每次改权限代码必跑。
