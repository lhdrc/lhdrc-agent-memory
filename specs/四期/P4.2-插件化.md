| 字段 | 值 |
|---|---|
| ID | P4.2 |
| 状态 | in_progress（A 档本仓 + 独立插件仓已接线；未 npm publish；P42-13 未自动化） |

| 对应架构 | 08 D1/D14/D17/D18；agent **不**把直接读仓文件当主 API |

> **与 P4.1 的关系**：P4.1（MCP/REST/Claude Code）仍后置、未获要求不实现。本期是独立访问面切片：把已稳定的 core 接到 DSH。不经过 MCP。

本仓 CLI 与测试仍用 **Bun**。插件进程是 **Node**。产品行为不得因换运行时变少。

## 1. 目标

1. **本仓**：core 生产路径不再依赖 Bun 专有 API，可被 Node `import`  
2. **本仓**：`@lhdrc/core` 可 npm 发布（JS 构建产物 + 运行时资源）  
3. **独立 git 仓**：DSH 插件依赖 npm 上的 `@lhdrc/core`，导出 Cordis `apply(ctx)`，注册记忆工具与 prompt section  
4. 写入仍只经 core（`compileSession` / `WriteQueue` / 索引 hook）；插件不复制写路径、不直接 `writeFile` 记忆 md  
5. Agent 主路径是工具，不是 `cat brains/`  

## 2. 非目标

- P4.1 MCP / REST / `memory serve` / Claude Code 适配器  
- P6.5 Cursor 模板  
- 把 `forget` / `refine` / `dream` / entity merge / `eval` / `rebuild-index` 做成 DSH 工具（继续 CLI）  
- 把 DSH `ctx.sessions` 日志当知识库；禁止把整场 transcript dump 进 `sources/`  
- 插件仓内再实现一套检索/蒸馏  
- 无 Key 时用启发式冒充 `compileSession`（仍 `E_DISABLED`；escape 仍是 `--no-extract` 语义的显式 note，A 档工具默认不提供这条 escape）  
- 找不到 `memory.yml` 时静默 `init`  
- 改 DeepSeek Harness 源码  
- 本仓改成以 Node 为默认测试运行时

## 4. 本仓改动（A 前置）

### 4.1 Node 兼容封装

生产路径禁止再出现 `Bun.file` / `Bun.spawn` / `import.meta.dir`。抽到 `packages/core/src/util/`（名称可调，契约如下）：

| 现用 | 替换 | 调用方 |
|---|---|---|
| `import.meta.dir` | `hereDir(import.meta.url)` → 当前模块目录 | `index/engine.ts`、`schema/loadPack.ts` |
| `Bun.file(path).text()` | `readFile(path, "utf8")` | `ensureSchema` 读 `schema.sql` |
| `Bun.spawn({ cmd: ["git", …] })` | `node:child_process` `execFile("git", args, { cwd })`，捕获 stdout/stderr/exitCode | `repo/git.ts` `runGit` |

约束：

- 不走 shell 拼接命令  
- `runGit` 的 `{ stdout, stderr, exitCode }` 语义与现网一致（现有 git 测例不得改期望）  
- CLI 的 `Bun.stdin`、`bun:test`、`Bun.spawn` 测例 **可以保留**（本仓仍 Bun 跑 CLI/测试）  
- 封装必须在 **Bun 与 Node 都能跑**；本仓回归仍 `bun test packages/core/tests/`

### 4.2 npm 分发 `@lhdrc/core`

当前 `main`/`exports` 指向 `src/index.ts`，Node 无法当库用。发布要求：

| 项 | 要求 |
|---|---|
| 构建 | 产出 `dist/*.js` + `.d.ts`（工具不限：`tsc` 或等价） |
| `exports` | `"."` 指向构建产物，不再指向裸 `.ts` 作为发布入口 |
| `files` / 打包 | 必须含 `schema.sql`、`schema-packs/`（及构建后仍能 `hereDir` 解析到它们） |
| 依赖 | 继续声明 `@electric-sql/pglite`、`yaml`、`pg`；不把 Bun 当 runtime 依赖 |
| 范围 | **只发 core**；CLI 不必发 |

未发布前，独立插件仓可用 `file:` / link 开发；**「依赖 npm 分发」以 registry 上的版本为准**。漏打 `schema.sql` / pack → Node 侧 `ensureSchema` / `loadPack` 失败，视为发包缺陷（P42-06）。

本仓 `bun run memory` 与 `bun test` **不**改成必须先 build。

## 5. 插件仓（独立 git 仓库）

不进本 monorepo 的 `packages/adapters/`。建议 npm 名 `dsh-df-memory`（或 `@df-memory/dsh`），`dependencies` 只对 `@lhdrc/core` 的 **已发布版本**。

```
dsh-df-memory/
  package.json          # dsh.bundle；依赖 @lhdrc/core
  cordis.patch.yml      # insert 本包
  src/index.ts          # name / inject / apply / Schema
  src/host.ts           # workspace → repoRoot / brain / queue / db
  src/tools.ts          # 三工具
  src/prompt.ts         # section 文案
  src/errors.ts         # MemoryError → 工具 JSON
```

Cordis / `defineTool` **只出现在插件仓**。core 不依赖 `@deepseek-ai/*`。

### 5.1 插件形态

```ts
export const name = "df-memory"
export const inject = ["tools", "systemPrompt"]

export function apply(ctx: Context) {
  // 解析 config → host
  // ctx.systemPrompt.section(…)
  // ctx.tools.register(memory_query | memory_read | memory_remember)
  // ctx.effect(() => () => host.close())  // 关 PGLite / 释放资源
}
```

注册必须经 `ctx`，以便卸载时自动摘掉工具与 section。

### 5.2 工作区映射

DSH Web 选中的工作区写在 **`SessionHeader.cwd`**（工具 `execute` 的 `exec.agent.session.header.cwd`）和 `ctx.workspaceRegistry`，**不是** `dsh` 进程的 `process.cwd()`。缺省查找不得只用进程 cwd。

| 输入 | 行为 |
|---|---|
| `config.repoRoot` 有值 | 绝对路径直接用；相对路径相对会话 cwd（再退回其它起点） |
| `DF_MEMORY_ROOT` | 显式覆盖起点 |
| 缺省 | 按序尝试：会话 `cwd` → `DSH_CWD`/`DSH_WORKSPACE` → `workspaceRegistry.list()`（`updatedAt` 新者优先）→ `process.cwd()`；每一项向上找 `memory.yml`（同 `findRepoRoot`） |
| 找不到仓 | 三个工具均返回结构化错误 `E_NOT_FOUND`（或 `E_USAGE` + 明确「先 memory init」），**不写盘、不 init** |
| `config.brainId` | 缺省用仓内 `brain_id` |

`created_by`：`dsh:{agentId}`，`agentId` 缺省 `dsh`。  
鉴权：`authorize({ channel: "cli", … })`（同机进程内 = trusted local）。不新开 `AuthChannel`。需要 `agent_id` 收窄时走现有 `applyAgentScopeFromId`。

### 5.3 配置（cordis.yml `config`）

```yaml
repoRoot: null          # 默认：工作区向上找 memory.yml
brainId: null           # 默认：仓内 brain_id
agentId: dsh
autoBuffer: false       # A 必须 false；B 才可 true
autoCompileOnEnd: true  # 仅 B
injectOnGate: true      # 仅 B
```

A 实现必须忽略（或拒绝）把 `autoBuffer` 当成已交付。

### 5.4 Prompt section

`ctx.systemPrompt.section`：

- `name`: `df-memory`
- `order`: 落在工具指引带（约定 100–199），不得 `complete: true`
- 文案必须包含：存在本地记忆仓；回忆用 `memory_query`；读原文用 `memory_read`；写入用 `memory_remember`；**禁止把直接读 `brains/` 文件当主 API**

### 5.5 工具契约

与 CLI 共用 core 函数；参数名面向模型。失败体：`{ "code": "<ErrorCode>", "message": "…" }`，不抛未捕获异常到 harness（可转成工具错误结果）。

| 工具 | 参数 | 映射 | 成功体要点 |
|---|---|---|---|
| `memory_query` | `query: string`；`limit?: number`；`mode?: conservative\|balanced\|tokenmax` | `hybridQuery` / `hybridQueryDetailed`（同 CLI `query` 默认 mode） | hits：`path`、`title`、`score`、snippet；path 相对仓根 |
| `memory_read` | `path: string`；`layer?: l0\|l1\|l2` | `readNode` | 与 CLI `read` 同层语义 |
| `memory_remember` | `body: string` | `compileSession`（须 `complete()`） | `session_id`、`kept`、`dropped`、`errors`；无 provider/key → `E_DISABLED`，**不写 L0** |

A 档 `memory_remember`：

- 一次调用 = 一场（或当前策略下的一次）compile，**不是** `--buffer`  
- 不把 DSH 对话历史偷偷塞进 inbox  
- 索引：compile 走 `WriteQueue` → `onFilesWritten`，与 CLI 相同，**不**为此全量 `rebuild-index`

`memory_query` 与 CLI `query` 在同一仓、同一 `mode`/`limit`/brain 下，返回 **path 集合一致**（顺序允许分差，因 RRF 并列）。

## 6. 错误与 LLM

| 情况 | 码 | 写盘 |
|---|---|---|
| 无记忆仓 | `E_NOT_FOUND` 或 `E_USAGE` | 否 |
| 路径越界 | `E_PATH_ESCAPE` | 否 |
| 无节点 | `E_NOT_FOUND` | 否 |
| compile 无 Key / provider=off | `E_DISABLED` | 不写 L0；inbox 可按 P6.3 标 failed |
| WRITE_FORMAT / 校验 | `E_VALIDATION` | 否 |
| 索引失败 | `E_INDEX` warn；md 已写则保留（D1） | 文件保留 |

A 档 **不**把 DSH `ctx.llm` 接到 `complete()`。仓内 `llm.provider=off` 或无 Key → `memory_remember` = `E_DISABLED`。B 档的 bridge 另开，不得改变 A 这条合同。

## 9. B 档（实现迁八期）

> **2026-08-15**：B 档从四期 DoD 迁出。挂钩 + `memory_remember` 异步 + 统一任务队列以 [`../../八期/P8.1-session-hook-async.md`](../../八期/P8.1-session-hook-async.md) 为准。本节保留概念事件，避免旧文档断链。

产品要：agent 每轮 user/assistant 进 inbox（七期 CLI 只做了 `remember --buffer`）。

```
agent/session-start     → 打开 inbox session
session/event 文本轮    → appendSessionTurns（autoBuffer: true）
窗口满                  → 已有 P7.3 compile
会话结束 / agent dispose → endSession
agent/pre-step          → shouldQueryMemory；命中则检索并 agent.inject(top-k)
卸载                    → 关索引连接；不把 DSH log 写成 L0
```

可选：仓内无 Key 时用 `ctx.llm` 适配 `complete()`；有 Key 仍以 `memory.yml` 为准或文档锁定单一来源。  
`autoBuffer` 默认在 B 开启。失败可观测，fail-open 不得把 transcript 写入 `sources/`。

> **bridge 扩展（已落地，随 0.2.1）**：注入的 `llm` 不止用于 compile 抽取，还经
> `compileSession → maybeLazyDistillAfterCompile` 贯通懒蒸馏（judge/refine/abstract），
> `kill_switch.distill` 仍优先。core 导出 `judgeDistillWithComplete` 等 5 个
> `*WithComplete` helper，bridge 与 EnvMock 共用同一 complete 路由。
> 宿主侧注意：**`ctx.llm` 属性不可读**（llm 不在插件 inject 列表），必须走规范访问
> `ctx.get("llm")`（与官方 `dsh-tool-fs` 一致）。

B 验收已锁在八期 P8.1（P81-10 起），不以本段草案为准。
