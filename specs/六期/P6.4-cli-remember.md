# Spec P6.4 — `remember` / `ingest --adapter session`

| 字段 | 值 |
|---|---|
| ID | P6.4 |
| 状态 | done |
| 依赖 | P6.3；P5.8（`ingest` 命令面，**不**复用逐行 `ingestJsonl`） |
| 对应架构 | D9；六期选择 1（CLI 为运输） |

## 1. 目标

1. `memory remember --body "…" [--dry-run] [--json] [--extract/--no-extract]`  
2. `memory ingest --adapter session --input <file> [--dry-run] [--json] [--continue-on-error] [--retry <id>]`  
3. 两条路径共用 `archiveSession` + `compileSession`（**摄入入口**）；不把 session 推进逐行 `IngestAdapter.map`  
4. `--dry-run`：不写 inbox、不写 sources  
5. `--retry <sessionId>`：有 `extracted.json` 则只补写盘；否则重跑 Extractor  
6. `memory inbox list [--json]`：列出 pending/failed/done  
7. 凡实际 archive 的命令，**即使无 `--json` 也打印** `session_id=…`  
8. HELP 列出 session、dry-run、retry、inbox  

## 2. 非目标

- 改 generic-jsonl / df-app 行为  
- Cursor hook（P6.5）  
- `--create-entities`  

## 3. 技术方案

### 3.1 命令

```
memory remember --body "…" | --body-file <path> | stdin
    [--dry-run] [--json] [--extract | --no-extract] [--source <id>]

memory ingest --adapter session --input ./session.jsonl
    [--dry-run] [--json] [--continue-on-error] [--retry <sessionId>] [--source <id>]

memory inbox list [--json] [--status pending|failed|done]
```

- `remember` 无 body / body-file / stdin → `E_USAGE`  
- `--no-extract`：仅 `remember` 合法；跳过 `complete`，当一条 `note`。`ingest --adapter session --no-extract` → `E_USAGE`  
- `--extract`：默认即走编译器（须 LLM 或测试 mock）  
- `provider=off` 且未 `--no-extract` → `E_DISABLED`，提示配置 `llm.provider` 与 API key  
- `remember --body` 视为单条 `user` turn  

`ingest --adapter session`：解析整个文件为 turns 数组（JSONL 或 JSON 数组），**一次** archive + compile。文件里每一行是 turn，不是节点。

`--retry`：忽略 `--input` 的 turns（可省略 `--input`）；`loadSession` 后按 P6.2/P6.3：有检查点则只补 `captureWrite`，`done` 则返回原 paths。

无 `--json` 时 stdout：每条 kept path 一行，最后一行 `session_id=<id>`（dry-run 不打 session_id）。

### 3.2 `--json`

```json
{
  "session_id": "…",
  "kept": [{ "type": "decision", "title": "…", "path": "brains/…", "links": [{ "to": "alice" }] }],
  "dropped": [{ "reason": "duplicate|noise|empty", "excerpt": "…" }],
  "unresolved": ["网关"],
  "errors": []
}
```

dry-run 无 `session_id`（未归档）或显式 `null`；`kept[].path` 省略。

退出码：成功 0；校验/非法输入 2；`E_LLM` / 系统 1。`--continue-on-error` 且仅有单条校验错：好条落盘、退出 2（与 P5.8 一致）。整场 LLM 失败：退出 1，sources 无新文件。

### 3.3 适配器注册

`ingest --list-adapters` 增加 `session`。实现上：CLI 对 `session` **分支**到 `compileSession`，不要把 `session` 注册成 `IngestAdapter.map`。

可选包 `packages/adapters/ingest-session/`：只负责「文件/stdin → `Turn[]`」+ fixture；compile 仍在 core。

### 3.4 模块落点

| 模块 | 路径 |
|---|---|
| remember | `packages/cli/src/commands/remember.ts` |
| inbox | `packages/cli/src/commands/inbox.ts` |
| ingest 分支 | `packages/cli/src/commands/ingest.ts` |
| 解析 turns | `packages/adapters/ingest-session/` 或 `packages/core/src/compile/parse.ts` |
| fixture | `packages/adapters/ingest-session/fixtures/`（决策句 / 噪声 / 挂链） |

## 4. 验收

| ID | 功能点 | Given / When / Then |
|---|---|---|
| P64-01 | dry-run 不写盘 | fixture 含决策句 → `ingest --adapter session --dry-run --json` → kept≥1；无新 md；无 inbox 目录 |
| P64-02 | remember | mock complete + `--body` 「我们决定…」→ kept≥1 且有 path |
| P64-02b | 无模型 | `provider=off` 的 `remember --body "我们决定 x"` → `E_DISABLED`，无新 md |
| P64-03 | 无 body | `remember` 无参数 → `E_USAGE` 退出 2 |
| P64-04 | session ingest | `--input` fixture → inbox pending→done；sources 有 md |
| P64-05 | list-adapters | 含 `session`（仍含 generic-jsonl、df-app） |
| P64-06 | 不走逐行 map | 两行 user/assistant 的 session **不是**两篇 note（除非启发式/LLM 真抽出两条） |
| P64-07 | retry LLM | mock LLM 失败后 `--retry <id>` + mock 成功 → 编出 kept；有新 md |
| P64-07b | retry 不重跑 LLM | 写盘中途失败后 `--retry` → spy `complete` 调用次数不增加 |
| P64-08 | HELP | `remember --help` / `ingest --help` / `inbox --help` 含 session、dry-run、retry、list |
| P64-09 | 既有 ingest | generic-jsonl 两行 fixture 口令仍绿（P58-02） |
| P64-10 | 打印 id | `remember --body "我们决定 x"` 无 `--json` → stdout 含 `session_id=` |
| P64-11 | inbox list | 一次失败的 ingest 后 `inbox list --json` → 该 id `status=failed` |
