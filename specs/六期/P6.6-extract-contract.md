# Spec P6.6 — 提取合同（类型说明书 + 已有记忆）

| 字段 | 值 |
|---|---|
| ID | P6.6 |
| 状态 | done |
| 依赖 | P6.3、P6.1、P5.3（`hybridQuery` 只读） |
| 对应架构 | 08 §6.3 prompt 即规格；学 OpenViking **schema-driven 提取**，不抄 11 类记忆 / ReAct |

> **落盘 schema 不改。** `problem-tree` 仍是文件类型与路径模板；会话摄入仍只产出 `decision | lesson | note`。  
> 本 Spec 补的是：**给模型看的类型合同、提取前已有条目、原文锚点、一次 JSON 修复**。仍是单次产品路径 `complete()`（修复是同 purpose 的第二次调用）。

## 1. 目标

1. `session-extract-v1.md` 按三类型写成合同（记什么 / 不记什么 / 标题禁令 / 拆分对照），不是一篇笼统作文  
2. user prompt 带 **Session Time**、编号 turns、以及可选的 **Already in the knowledge base**  
3. item 可带 `source_turns`；越界则丢该条，不整场失败  
4. `complete` 返回非 `{items: array}` 时 **再调一次** 修复；第二次仍坏 → 现有 `E_LLM`  
5. 提取前用现有检索捞 top-N 标题+摘要给模型；失败则省略该节，不阻断 compile  

## 2. 非目标

- 增加 schema 类型（不做 profile / events / preferences 等 11 类）  
- ReAct / 给模型 `read` `search` 写工具  
- L0 upsert / patch 旧文件（仍 ADD-only；写前余弦/全等去重保留）  
- 自动 `entity create`（六期不做；七期见 P7.4，仅 compile）  
- 把提取说明书搬进 schema pack YAML（pack 继续只管路径与 `schema_types`）  
- 改 P6.5 门控；改人手 `capture`  

## 3. 与 OpenViking 的对照

| OV | 本 Spec | 为何改 |
|---|---|---|
| 每类 YAML → JSON Schema field description | 一篇 `session-extract-v1.md` 内按三类型分节 | 类型已锁定；不必动态生成 Pydantic |
| ExtractLoop + read/search | **一次** `complete`（+ 最多一次 JSON 修复） | P6.3 已锁定；热路径不持锁调 LLM |
| prefetch 旧 profile 再 patch | prefetch 标题/摘要，模型 **只许新增** | D17 ADD-only |
| `ranges` 必填 | `source_turns` **可选**；有则校验 | 降低空会话失败率 |
| 系统生成 URI | 仍禁止模型输出 path / wikilink / frontmatter | 与 P6.3 一致 |

## 4. Prompt 合同

权威文本：[`packages/core/resources/session-extract-v1.md`](../../packages/core/resources/session-extract-v1.md)。

实现读该文件为 `system`。必须仍满足 P63-11（含 `"items"`、`{ "items": [] }`、`Few-shot`、`decision`）。

### 4.1 类型合同（system）

| type | 记 | 不记 | 标题 |
|---|---|---|---|
| `decision` | 已确认的选择/变更/以后怎么做 | 助手猜测、未拍板的选项、纯执行过程 | 一事一名；禁止「项目讨论」「会议纪要」等桶名 |
| `lesson` | 根因 + 以后不要再犯 | 一次性报错堆栈、未复盘的失败 | 写可迁移的禁令，不写这次 diff |
| `note` | 用户明确要求记住，或以后要用的稳定事实 | 寒暄、ack、整场 transcript | 具体；禁止把整场会话做成一条 note |

独立结论拆开：一场里多个互不依赖的决策/教训 → **多条** item。  
body 必须脱离会话可读。输出语言与 **user turns** 一致；代码标识符原样保留。

### 4.2 user prompt 形状

```
## Session
**Session Time:** YYYY-MM-DD HH:MM UTC (Weekday)
Relative times (e.g. yesterday) are based on Session Time, not the model's clock.

## Already in the knowledge base (do not re-extract; only emit genuinely new items)
- <title>: <snippet>
  （无命中或 prefetch 关闭/失败则整节省略）

## Conversation
1. user: …
2. assistant: …
```

- Session Time：第一则带 `at` 的 turn；否则 compile 当时的 UTC  
- Conversation 编号与 P6.3 相同：只编 `user`/`assistant`，`system`/`tool` 不送模型  
- Already-in-kb **不是** `<df-memory-context>`；compile 仍先剥离注入块，prefetch 用剥离后的 turns  

### 4.3 `source_turns`

```json
{ "type": "decision", "title": "…", "body": "…", "source_turns": [1, 3] }
```

- 可选。省略或 `[]` 合法  
- 若出现：必须是整数数组，且每个 ∈ `[1, N]`（N = 本次 Conversation 编号上限）  
- 非法 → 该条 `E_VALIDATION`，不写盘，不令整场 failed  
- 校验后丢弃，不写入 md / frontmatter  

## 5. 技术方案

P6.3 §3.2 步骤 7 替换为：

```
7. 否则：
     无可用 LLM → markFailed E_DISABLED
     prefetch：hybridQuery(user turns 拼接，limit=compile.prefetch_topn)；失败→[]
     user = §4.2
     complete({ purpose:"compile", system: session-extract-v1.md, prompt: user })
     非 {items: array} → 再 complete 一次（同一 system；prompt = user + 修复句）
     第二次仍坏 → markFailed E_LLM
```

prefetch **锁外**、fail-open（索引未就绪 / 查询抛错 → 当空列表）。  
`prefetch_topn: 0` 关闭。默认 **5**。命中只展示 `title` + `snippet`/`abstract`，**不展示 path**（防模型学着输出 path）。  
查询串：剥离后的 user 文本拼接，截断 500 字；无 user 文本则用全部编号 turns 文本，再截断。

修复句（固定英文，追加在 user prompt 末尾）：

```
Previous response was not a JSON object with an "items" array. Return only that JSON object.
```

写前去重、linkify、`queue.execute` 仍按 P6.3。

### 5.1 配置

```yaml
compile:
  dedupe_cosine: 0.95
  dedupe_window: 200
  max_input_chars: 32000
  tool_max_chars: 2000
  prefetch_topn: 5   # 0=关闭；已有仓缺该键时按 5
```

旧仓无此键不报错。
