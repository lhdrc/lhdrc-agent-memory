# Spec P6.1 — LLM complete API

| 字段 | 值 |
|---|---|
| ID | P6.1 |
| 状态 | done |
| 依赖 | 现有 `packages/core/src/llm/` 桩；建议 P5.1 cost cap |
| 对应架构 | 08 §6.3 prompt 即规格；六期选择 1 |

> 编译器（P6.3）组 prompt；本 Spec 提供记忆系统内调模型的 API。  
> **会话摄入（remember / ingest session）必须能打到真实或测试注入的 `complete()`。** `provider=off` 不是产品路径。

## 1. 目标

1. `LLMProvider.complete(req) → { text, usage? }` 成为唯一补全入口  
2. `llm.provider=openai` 时 **真打** Chat Completions（结束「factory 一律 Noop」）  
3. `provider=off`：`complete` 抛 `E_DISABLED`；编译器不得在 off 路径调用它  
4. kill-switch `llm.kill_switch.compile` 与日 cap：跳过并让调用方记失败，不写 L0  
5. 单测用 mock provider，默认 CI 不联网  

## 2. 非目标

- 会话提取语义（P6.3 持 prompt / JSON parse）  
- `extractSession` 任务方法  
- 把 abstract/distill 全部改走 `complete`（可后置；本 Spec 不强制重构 P2.2/P5.2）  
- 默认打开联网；默认模型调用  

## 3. 技术方案

### 3.1 接口

```ts
type CompletePurpose = "compile" | "extract" | "abstract" | "distill" | "other";

type CompleteRequest = {
  prompt: string;
  system?: string;
  purpose: CompletePurpose;
};

type CompleteResult = {
  text: string;
  usage?: { prompt_tokens: number; completion_tokens: number };
};

interface LLMProvider {
  readonly id: string;
  complete(req: CompleteRequest): Promise<CompleteResult>;
  // 既有方法保留；本 Spec 不删
}
```

| 实现 | `complete` |
|---|---|
| `NoopLLMProvider` | 抛 `E_DISABLED`（message 含 `llm.provider=off`） |
| `OpenAILLMProvider` | Chat Completions，见下 |

`OpenAILLMProvider`：`POST {base_url}/v1/chat/completions`（`llm.base_url` 默认 `https://api.openai.com`）。  
请求：`model`、`temperature: 0`、`max_tokens: 4096`、timeout 60s；messages = optional system + user prompt。不设 `response_format`（编译器剥围栏）。  
成功后 `appendCostEntry({ kind: "compile", tokens_in, tokens_out, model })`。  
调用前 `wouldExceedCap` → `E_DISABLED` + `skipped_reason=cost_cap`。  
`kill_switch.compile` 且 `purpose=compile` → `E_DISABLED`（编译器先查一层，provider 再挡一层）。

`createLLMProvider`：`off` → Noop；`openai` → OpenAI 实现（缺 key 时第一次 `complete` 抛 `E_DISABLED`，不在 factory 静默变 Noop）。

### 3.2 配置（`memory.yml` 增量）

```yaml
llm:
  provider: off            # off | openai；会话摄入需要 openai + key（或测试注入 mock）
  model: gpt-4o-mini
  openai_api_key_env: OPENAI_API_KEY
  base_url: https://api.openai.com
  distill: true
  extract: false
  kill_switch:
    distill: false
    abstract: false
    extract: false
    compile: false
```

默认 `provider=off`、`kill_switch.compile=false`。init 模板补 `model` / `compile` 两行，不改变现有默认行为。

HTTP 失败、非 2xx、空 choices → 抛 `E_LLM`（新增错误码，见 [`../mvp/00-conventions.md`](../mvp/00-conventions.md)）。不在 provider 内重试（重试由 inbox / `--retry` 承担，P6.2）。

cost cap 已超 → 抛 `E_DISABLED`，`details.skipped_reason=cost_cap`（与 P5.1 enrich 一致：不写盘）。

## 4. CLI

无新命令。会话 CLI（P6.4）在 `provider=off` 时对 `remember`/`ingest session` 返回 `E_DISABLED`（P63-06）。本 Spec 单测 mock `complete`。

## 5. 验收

| ID | 功能点 | Given / When / Then |
|---|---|---|
| P61-01 | off 禁用 | `provider=off` → `complete()` 抛 `E_DISABLED` |
