# Spec P6.2 — Inbox 归档

| 字段 | 值 |
|---|---|
| ID | P6.2 |
| 状态 | done |
| 依赖 | M1（`.dfmemory/` 布局） |
| 对应架构 | 六期选择 2；学 OpenViking「先归档后提取」，**不**把 transcript 写入 `sources/` |

> 原文是工作队列，不是记忆。权威 L0 仍是 `brains/{id}/sources/` 下的 md（D1）。

## 1. 目标

1. 会话原文落 `.dfmemory/inbox/sessions/{brainId}/{sessionId}/`  
2. 状态二元：`pending` → `done` \| `failed`；**无** `.partial.json`  
3. LLM/编译失败：inbox 保留，标 `failed.json`，**不阻塞**下一次 archive  
4. 同 `sessionId` 已 `done` → 再 compile 为幂等 skip  
5. 不进索引、不进 `query`/`think`；gitignore  

## 2. 非目标

- 把 inbox 当 L0 节点 / 进 git flush（D18 不覆盖 inbox）  
- Token 阈值、Idle TTL、PreCompact、后台 sweep（无守护进程）  
- 跨仓复制 inbox  

## 3. 技术方案

### 3.1 布局

```
.dfmemory/inbox/sessions/{brainId}/{sessionId}/
  messages.jsonl      # 一行一个 turn；权威原文
  meta.json           # 见下
  extracted.json      # Extractor 成功后的检查点（待写/已写条目）；LLM 失败则无此文件
  failed.json         # 仅 status=failed 时存在
```

`meta.json`：

```ts
type InboxMeta = {
  session_id: string;
  brain_id: string;
  source_id: string;
  created_at: string;          // ISO-8601
  status: "pending" | "done" | "failed";
  created_by: string;
  compiled_at?: string;
  kept_paths?: string[];       // 相对仓根；done 时
};
```

`failed.json`：`{ "skipped": true, "error": { "code": "E_LLM" | string, "message": string } }`

`messages.jsonl` 行：

```ts
{
  role: "user" | "assistant" | "system" | "tool";
  text: string;
  at?: string;
}
```

`tool` 行：归档时截断至 `inbox.tool_max_chars`（默认 2000）；提取上下文默认不送 tool（P6.3）。

### 3.2 状态机

```
archiveSession(turns) → 写 messages.jsonl + meta status=pending
                         （tmp 文件 + rename，防写坏）
        │
        ├─ markDone(paths)  → status=done；删 failed.json（若有）
        ├─ markFailed(err)  → status=failed；写 failed.json；messages 不动
        │                    可带 kept_paths（写盘中途失败，D1 已落盘的留下）
        └─ 下一次 archiveSession（新 id）不受本次 failed 影响
```

- `done` 后再 compile：不重写 sources，返回已有 `kept_paths`。  
- `--retry`：同一 `sessionId`。若有 `extracted.json` → **不重跑 LLM**，只补 `captureWrite` 未完成条目；若无（纯 LLM 失败）→ 清 `failed.json`，status 回 `pending`，重跑 Extractor。  
- **禁止**在 inbox 里写结构化 L0 md。

### 3.3 API

```ts
// packages/core/src/inbox/session.ts
archiveSession(opts: {
  repoRoot: string;
  brainId: string;
  sourceId: string;
  createdBy: string;
  turns: Turn[];
  sessionId?: string;          // 缺省：UTC compact + 短随机
}): Promise<{ sessionId: string; dir: string }>;

loadSession(repoRoot, brainId, sessionId): Promise<{ meta: InboxMeta; turns: Turn[] }>;
markDone(repoRoot, brainId, sessionId, keptPaths: string[]): Promise<void>;
markFailed(repoRoot, brainId, sessionId, error: { code: string; message: string }, keptPaths?: string[]): Promise<void>;
listInbox(repoRoot, brainId, status?: InboxMeta["status"]): Promise<InboxMeta[]>;
```

路径越出 `.dfmemory/inbox/sessions/{brainId}/` → `E_PATH_ESCAPE`。未知 id → `E_NOT_FOUND`。

### 3.4 gitignore

根 `.gitignore` 增加 `.dfmemory/inbox/`。`00-conventions.md` §6 同步。

## 4. CLI

列表与 retry 见 P6.4（`memory inbox list`、`--retry`）。本 Spec 单测可直接调 archive API。

## 5. 验收

| ID | 功能点 | Given / When / Then |
|---|---|---|
| P62-01 | 落盘 | archive 三行 turns → `messages.jsonl` 三行；`meta.status=pending` |
| P62-02 | 不进检索 | archive 后 `query` 标题/正文词 **不**命中 inbox 文本 |
| P62-03 | 失败保留原文 | markFailed → `failed.json.skipped=true`；`messages.jsonl` 仍在 |
| P62-04 | 不阻塞 | 第一次 markFailed 后第二次 archive **新** sessionId 成功 pending |
| P62-05 | 原子写 | 中断模拟：目录内要么完整 messages+meta，要么没有半截 json |
| P62-06 | 越权 id | `sessionId` 含 `..` → `E_PATH_ESCAPE` |
| P62-07 | tool 截断 | tool.text 超长 → 落盘长度 ≤ 配置上限 |
| P62-08 | 检查点 | Extractor 成功后存在 `extracted.json`；纯 `complete` 失败则无此文件 |
