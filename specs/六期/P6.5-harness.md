| 字段 | 值 |
|---|---|
| ID | P6.5 |
| 状态 | done（§3 门控函数）；draft（§4 Cursor 模板） |
| 依赖 | P5.5 `think`/`find`；规则随 P6.4 交付；模板不阻塞六期主线 |
| 对应架构 | OpenViking 分层召回（意图 × 打分 × 检索）；**门控不调 LLM** |

> **主线**：`shouldQueryMemory` 纯函数 + 单测。  
> **增强轨**：Cursor hook / `/` 模板（§4）。  
> 学 OV 的分层，**不**学「每条用户消息先打一次 IntentAnalyzer LLM」。编码场景默认不查；命中门控才 `think`/`find`。

## 0. 与 OpenViking 的对照（规则如何定）

OV 三层：**LLM 意图分析 → 经验打分门控 → 检索参数**。VikingBot 默认经验召回还是关的，查询却偏主动（操作型/信息型都查）。

本产品（coding agent + 本地仓）收成：

| OV | 本 Spec | 为何改 |
|---|---|---|
| IntentAnalyzer（LLM, t=0）判任务类型 | **词表 + 打分**，零 LLM | 每条消息先打 LLM 会拖编码、费额度；门控必须 fail-open、可单测 |
| 操作型/信息型都查，对话型不查 | 同样三分，但 **score≥3 才查** | 避免「实现一个函数」也全库检索 |
| 上下文覆盖（摘要+近 5 条） | `dedupe_window` + 与上次注入 query 的词重叠 | 无会话守护进程时的等价物 |
| 每类最多 5 条 TypedQuery | **一条** query（用户这句或拟改对象名） | 我们只有一个仓，不拆 skill/resource URI |
| 经验分 ≥3 才查 experience | 并入同一张分表；命中后用 `think` 分桶 | 已有 `memory think`（skills/experiences/notes） |
| find vs search 选检索器 | `find` = 平面检索；`think` = 分桶（操作型/启动） | 不引入 OV 层级目录下钻 |
| `<openviking-context>` 防污染 | 注入用 `<df-memory-context>`；**compile 前剥离**（P6.3） | 召回块不得再变成新 L0 |
| agentExperience.enabled 默认 false | 门控**默认开**（函数存在即用）；hook 默认 fail-open | 无 hook 时人仍可 `/memory` |

**不抄**：Token 20K / Idle TTL / PreCompact；Rerank AK；层级 viking:// 下钻。

## 3. 门控（主线，随 P6.4 交函数）

### 3.1 硬规则（先于打分）

**强制查**（跳过打分）：

| 条件 | command | query |
|---|---|---|
| `sessionStart` / 本 session 第一条用户消息 | `think` | 用户这句 |
| `/memory <q>` 或「查一下记忆」 | `find`（有参数用参数；否则用原句） | 见左 |
| 配置 `recall.force=true`（测试/cron） | `think` | 用户这句 |

**硬跳过**（直接 `null`）：

| 条件 |
|---|
| 空串，或 trim 后 Unicode 长度 < `min_query_chars`（默认 **4**；中文「以前怎么做」要能过） |
| 文本已含 `<df-memory-context`（防重复注入） |
| `bypass=true` |
| 与上次实际查询 **完全相同** 且在 `dedupe_window_s`（默认 120）内 |

### 3.2 任务三分（词表，对齐 OV）

先打标签，再打分。可多标签。

| 类型 | 特征（中英） | 倾向 |
|---|---|---|
| **操作型** | 实现/修复/重构/部署/写入/create/implement/fix/deploy/build | 查，`think` |
| **信息型** | 什么是/为什么/如何理解/以前/上次/谁决定/有没有踩过/how did we | 查，`find`（问历史）或 `think`（要经验） |
| **对话型** | 你好/谢谢/好的/ok/继续/再试/修一下/lint 一下/翻译/总结这段 | 不查 |

### 3.3 打分（确定性；学 OV 经验门）

```
shouldQueryMemory({ userText, ctx }) →
  硬跳过? null
  强制? { query, command }
  score = 0
  命中则加减（可叠加，同类不重复加）
  score >= threshold（默认 3）? { query, command } : null
```

| 信号 | 分 |
|---|---|
| 问历史词表（以前/上次/谁决定/踩过/我们约定/last time/how did we） | +3 |
| 拟改约定（依赖、目录结构、错误码、鉴权、公共 API、`memory.yml`） | +3 |
| 操作型动词（上表） | +3 |
| 执行动词（测试/构建/调试/test/build/debug/run） | +2 |
| 失败信号 **且** `ctx.failCount >= 2`（报错首行或症状） | +2 |
| 工程对象（路径、`ErrorCodes`、hook、API、pack id） | +2 |
| 经验意图（踩坑/教训/best practice/avoid） | +1 |
| 对话型（上表） | −3 |
| 纯知识问答、无工程对象、无执行/操作动词（「什么是递归」类） | −2 |
| 与 `ctx.lastInjectedQuery` 词重叠率 ≥ 0.5 且在去抖窗内 | −3 |

`query` 默认 = 用户这句；拟改约定时可用命中的对象名（如 `ErrorCodes`）。  
`command`：操作型或 `failCount≥2` 或 sessionStart → `think`；其余命中 → `find`。

可配（`memory.yml`，缺省如下）：

```yaml
recall:
  threshold: 3
  min_query_chars: 4
  dedupe_window_s: 120
```

### 3.4 检索怎么查（已有能力，不新造）

| command | CLI | 对应 OV |
|---|---|---|
| `find` | `memory find "<query>"` | 简单 `find()` 向量/混合 |
| `think` | `memory think "<query>"` | 带会话意图的分桶（skill/经验/L0） |

注入格式（防污染，P6.3 剥离）：

```
<df-memory-context query="…">
…think/find 的 L0 摘要…
</df-memory-context>
```

## 4. Harness（增强轨，draft）

Hook 只调 CLI；不实现 compile。fail-open。

| | Hook | `/` |
|---|---|---|
| 启动 | `sessionStart` → 强制 `think` | `/memory` |
| 中途 | `beforeSubmitPrompt` → §3 | `/memory` `/remember` |
| 结束 | `sessionEnd` → ingest session | `/memory-commit` |

模板落点仍为 `packages/adapters/cursor/`（hooks + 三条 command + SKILL + README）。  
`sessionEnd` 若无全文 transcript：不得假装导出；改用会话中追加 jsonl 或 `/memory-commit --input`。
