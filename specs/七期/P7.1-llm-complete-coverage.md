# Spec P7.1 — LLM complete 全覆盖

| 字段 | 值 |
|---|---|
| ID | P7.1 |
| 状态 | done |
| 依赖 | P6.1 `complete()`；P2.2 蒸馏方法；P5.1 `extractFacts`；P5.2 layers |
| 对应架构 | 08 §6.3–6.5；P6.1 非目标「不强制重构 P2.2/P5.2」本期收回 |

> P6.1 只保证会话 compile 能打到 `complete()`。生产 `OpenAILLMProvider` 的 `judgeDistill` 固定 skip、`refineExperience` 抛错、**无 `extractFacts`**，`layers refresh` 从不调 LLM。  
> 本期：**所有既有 LLM 方法都经 `complete()`**。不新增第二套 HTTP 客户端。

## 1. 目标

1. `OpenAILLMProvider`：`judgeDistill` / `refineExperience` / `generateAbstract` / `generateOverview` / `extractFacts` 均调用 `this.complete()`，再按 JSON 合同解析  
2. `EnvMockLLMProvider` 同样走 `complete()`（可按 purpose 覆盖 mock 文本），不再对 refine 抛 `E_DISABLED`  
3. `layers refresh`：`llm.provider=openai` 且 `kill_switch.abstract=false` 时调 `generateAbstract` / `generateOverview`；失败回退启发式，不回滚已有 md  
4. `capture --extract` / `llm.extract=true`：openai 走 `extractFacts`（不再因方法缺失静默启发式）  
5. `provider=off`：行为与今相同（distill skip；refine 不可用；extract/layers 启发式）  
6. 每种 purpose 有独立 prompt 资源文件  

## 2. 非目标

- 改蒸馏管线语义（那是 P7.2）  
- 改会话 compile prompt（P6.6）  
- 默认把 `llm.provider` 改成 openai  
- 用 LLM 判断「该不该查」（P6.5）  

## 3. 技术方案

### 3.1 purpose 映射

| 方法 | `CompletePurpose` | kill_switch | prompt 资源 |
|---|---|---|---|
| `complete`（会话） | `compile` | `compile` | `session-extract-v1.md`（已有，调用方组） |
| `extractFacts` | `extract` | `extract` | `packages/core/resources/extract-v1.md`（已有则复用） |
| `generateAbstract` | `abstract` | `abstract` | `packages/core/resources/abstract-v1.md` |
| `generateOverview` | `abstract` | `abstract` | `packages/core/resources/overview-v1.md` |
| `judgeDistill` | `distill` | `distill` | `packages/core/resources/distill-judge-v1.md` |
| `refineExperience` | `distill` | `distill` | `packages/core/resources/distill-refine-v1.md` |

`CompletePurpose` **不扩枚举**（已有 `compile \| extract \| abstract \| distill \| other`）。cost log 的 `kind` 用 `req.purpose`。

`kill_switch.distill` 且 purpose=`distill` → `complete` 抛 `E_DISABLED`（与 compile 对称）。P6.1 只挡了 `compile`，本期补 `extract` / `abstract` / `distill`。

### 3.2 JSON 合同（模型输出）

**judgeDistill** → parse 为 `DistillDecision`：

```json
{ "candidate": "skip"|"create"|"none", "item": "merge"|"delete"|null, "targetExpId": "…"|null, "confidence": 0.0, "rationale": "…" }
```

缺字段 / 非法 `candidate` → 视为 `{ candidate: "skip", confidence: 0, rationale: "parse_error" }`（fail-open，不写坏经验）。

**refineExperience** → `ExperienceResult`：

```json
{ "title": "…", "trigger": "…", "procedure": "…", "boundary": "…", "body": "…" }
```

非对象或缺 `title` → 抛 `E_LLM`（调用方 P7.2 / 结晶决定是否回退）。

**extractFacts** → `{ "facts": [ { "text", "event_type", "attributed_to", "at" } ] }`  
非法条丢弃；全非法 → 空数组（enrich 不回滚 md）。

**generateAbstract / generateOverview**：纯文本即可（剥 markdown 围栏）；空则调用方启发式。

JSON 修复：仅 `judgeDistill` / `refineExperience` / `extractFacts` 在 parse 失败时 **再 `complete` 一次**（同 purpose）；第二次仍坏则按上列 fail-open 或 `E_LLM`。abstract/overview 不修。

非法 `candidate` / 缺字段 → skip，**即使经验蒸馏偏 create 也不把 parse 失败当成 create**。

### 3.2a distill prompt 合同

权威文本：

- [`packages/core/resources/distill-judge-v1.md`](../../packages/core/resources/distill-judge-v1.md) → `judgeDistill` 的 `system`
- [`packages/core/resources/distill-refine-v1.md`](../../packages/core/resources/distill-refine-v1.md) → `refineExperience` 的 `system`（create / merge / **结晶** 同一份）

组装对齐 P6.6：system = 资源文件；user = 代码拼的结构化段。`CompletePurpose` 仍是 `distill`，不扩枚举，不加 `skill-crystallize-v1.md`。结晶 JSON 仍是 `ExperienceResult`；`verification` 由代码启发式写入 SKILL.md，模型若建议验收则放进 `body` 的 `## Verification`。

**judge 偏 create（经验层）：** L0 为 `decision` / `lesson`，或 `note` 能抽出可迁移的 trigger+procedure 时，默认 `candidate: create`。预筛为空 → create。仅当「已被某条 experience 覆盖」或「没有可迁移步骤」才 `skip`/`none`。`item: merge` = 同 trigger 互补；`item: delete` = 旧经验 `superseded`（**不删** `sources/`）。merge/delete 的 `targetExpId` 必须是 Existing 列表里的 id；编造 id → 代码当 noop。

**judge user prompt：**

```
## Existing experiences (prescreened; use these ids only)
- id: <ulid>
  title: ...
  trigger: ...
  snippet: ...

## Candidate source
path: sources/...
schema_type: decision|lesson|note
title: ...
---
<title + facts + body 截断>
```

`judgeDistill(existing: string[], candidate: string)` 签名不变：`existing` 每项已含 `id:` 行；`candidate` 含 `schema_type`。

**refine user prompt（system 不变，三种 Task）：**

```
## Task
Write a new experience from the candidate.
# 或 Merge the candidate into existing experience <id>. Keep old valid steps; add new ones.
# 或 Synthesize one reusable skill-shaped experience from the cluster. Generalize; drop instance-only names.

## Candidate
...

## Existing experiences
...
```

`ExperienceContext.task`: `create` | `merge` | `synthesize`（缺省 `create`）。`targetExpId` 仅 merge 需要。

### 3.3 封装形状

```ts
// OpenAILLMProvider / EnvMockLLMProvider 共用
async judgeDistill(existing: string[], candidate: string): Promise<DistillDecision> {
  const { text } = await this.complete({ purpose: "distill", system, prompt });
  return parseJudge(text);
}
```

禁止在 openai 实现里再写一套 fetch。`extractFacts` **必须存在**（不再 optional 缺失）。

`NoopLLMProvider`：

| 方法 | 行为 |
|---|---|
| `complete` | `E_DISABLED`（已有） |
| `judgeDistill` | `{ candidate: "skip", … rationale 含 provider=off }` |
| `refineExperience` | `E_DISABLED` |
| `generateAbstract` / `generateOverview` | 截断启发式（已有） |
| `extractFacts` | 可省略或抛 `E_DISABLED`；enrich 在 `provider=off` 时不调用 |

### 3.4 EnvMock 按 purpose 覆盖

| 环境变量 | 作用 |
|---|---|
| `DF_MEMORY_MOCK_COMPLETE` | 默认文本（任意 purpose） |
| `DF_MEMORY_MOCK_COMPLETE_COMPILE` | 覆盖 `compile` |
| `DF_MEMORY_MOCK_COMPLETE_DISTILL` | 覆盖 `distill` |
| `DF_MEMORY_MOCK_COMPLETE_EXTRACT` | 覆盖 `extract` |
| `DF_MEMORY_MOCK_COMPLETE_ABSTRACT` | 覆盖 `abstract` |
| `DF_MEMORY_MOCK_COMPLETE_FAIL` | 任意 `complete` 抛 `E_LLM`（已有） |
| `DF_MEMORY_MOCK_COMPLETE_LOG` | 追加 purpose 行（已有） |

查找顺序：purpose 专用 → 通用 → `""`。  
`judgeDistill` / `refineExperience` / `extractFacts` / `generateAbstract` **必须**调用 `this.complete()`，以便 LOG 与 FAIL 生效。

### 3.5 layers refresh

`packages/core/src/layers/refresh.ts`：

```
provider=openai && !kill_switch.abstract
  → generateAbstract(body) / generateOverview([body])
  → 抛错或空串 → heuristicAbstract / heuristicOverview
否则 → 仅启发式
```

`--json` 增加 `llm_abstract?: boolean`（该 path 是否用了模型结果）。`provider=off` 验收 P52-01 仍绿。
