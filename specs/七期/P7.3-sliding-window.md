# Spec P7.3 — 滑动窗口摄入

| 字段 | 值 |
|---|---|
| ID | P7.3 |
| 状态 | ready |
| 依赖 | P6.2 inbox、P6.3 `compileSession`、P6.4 CLI |
| 对应架构 | 六期 F11；学 OV 攒上下文再提取，**不做** Idle TTL / 守护进程 |

> 六期：每次 `remember` / `ingest --adapter session` 立刻 `compileSession`。  
> 本期：可选把 turns **追加进未关闭会话**；达上限或显式结束再 compile。无后台线程。

## 1. 目标

1. core：`appendSessionTurns` / `endSession`；打开中的会话原文仍只在 `.dfmemory/inbox/`  
2. 达 `window_max_turns` **或** `window_max_chars`（user+assistant 合计）→ 自动 `compileSession`（同现入口，一次 WriteQueue job）  
3. 未达上限：只 archive/append，**不**调 `complete`  
4. 显式结束：无论是否达上限都 compile 剩余 turns  
5. 默认 CLI 兼容：`remember` 无 `--buffer` 仍立即 compile（P6.4）  
6. `ingest --adapter session --window` 走窗口；`--end` 结束指定或当前 open 会话  

## 2. 非目标

- 守护进程、Idle TTL、token 20K、PreCompact  
- 改 `remember` 默认立刻 compile  
- `ingest --adapter session` 无 `--window` 时的一次 compile（保持 P6.4）  
- 把 inbox 进 git / 进检索  
- **agent 每轮自动 append**（Cursor/MCP/对话运行时）。本期只做 CLI `--buffer`；产品意图记在七期 README「以后再说」与 [`doc.md`](../../doc.md)  

## 3. 技术方案

### 3.1 配置（`memory.yml` / `compile` 节增量）

```yaml
compile:
  dedupe_cosine: 0.95          # 已有
  max_input_chars: 32000       # 已有，送模型截断
  window_max_turns: 20         # user+assistant 计数；≤0 视为未开窗口（--window 则 E_USAGE）
  window_max_chars: 16000      # 同角色合计 Unicode 长度
```

init 写入默认值。窗口触发 compile 时仍受 `max_input_chars` 约束（P6.3 §3.2 步 3）。

### 3.2 打开中的会话

每个 brain **至多一个** open 窗口：

```
.dfmemory/inbox/sessions/{brainId}/{sessionId}/
  messages.jsonl
  meta.json          # 增加 open?: boolean；status 仍 pending|done|failed
```

指针文件（gitignore 已覆盖 inbox）：

```
.dfmemory/inbox/sessions/{brainId}/.open
# 内容：session_id 一行
```

- `open=true` 且 status=`pending`：可 append  
- compile 成功 → `open=false`，删 `.open`（若指向该 id）  
- compile 失败 → status=`failed`，`open=false`，`.open` 清除；turns 保留；`--retry` 仍按 P6.2  

禁止两个 `.open`。第二场 `--window` 在已有 open 时 **追加到同一 id**（不新开）。`--session <id>` 可指定；若 id 已 done → `E_CONFLICT`。

### 3.3 API

```ts
appendSessionTurns(opts: {
  repoRoot: string; brainId: string; sourceId: string; createdBy: string;
  pack: SchemaPack; queue: FileMutationExecutor;
  turns: Turn[];
  sessionId?: string;     // 缺省：读 .open 或新建
  window: true;
}): Promise<AppendResult>

endSession(opts: {
  repoRoot: string; brainId: string; … queue, pack;
  sessionId?: string;     // 缺省：.open
}): Promise<CompileResult>
```

`AppendResult`：

```ts
{
  session_id: string;
  buffered_turns: number;     // user+assistant
  buffered_chars: number;
  compiled?: CompileResult;   // 仅当本次触发自动 compile
}
```

算法：

```
1. 解析 sessionId：显式 | .open | 新建 archiveSession(turns 暂空) 再写 .open
2. 追加 messages.jsonl（与 archive 同样截断 tool）
3. 计 user+assistant turns/chars（全文，含此前）
4. if turns>=window_max_turns OR chars>=window_max_chars
     → compileSession({ sessionId })   // retry 语义：load 已有 messages，跑提取
     → 清 .open
   else
     → 不 complete；返回 compiled 省略
```

`endSession`：无 open 且无 `--session` → `E_NOT_FOUND`。空 messages → `compileSession` 现有空 items 行为（markDone / dropped empty），不清未知文件。

窗口自动 compile 与 `endSession` **都走** P6.3（含 P6.6 prefetch、去重、linkify）。LLM 失败：inbox failed，已缓冲原文保留。

### 3.4 CLI

```
memory remember --body "…" [--buffer] [--json]
memory ingest --adapter session --input <file> [--window] [--session <id>] [--json]
memory ingest --adapter session --end [--session <id>] [--json]
memory inbox end [--session <id>] [--json]     # 可选别名，与 --end 同实现；P7.5 若做 inbox retry 可同文件
```

- `remember --buffer`：把 body 当一条 user turn append；达上限则 compile  
- `remember` 无 `--buffer`：P6.4 立即 compile（**不**碰 `.open`）  
- `ingest --window`：文件内全部 turns append；循环中每过上限 compile **一次**（余下 turns 留在**新** open 会话，避免一场超限只蒸前半却把后半标 done）  
  - 切分规则：按 turn 边界切成 ≤max 的窗口，每窗独立 sessionId；最后一窗未满则保持 open  
- `ingest` 无 `--window`：整文件一次 compile（P6.4）  
- `--end` 与 `--window` 同时 → `E_USAGE`  
- `provider=off`：append **允许**（不调 LLM）；自动/`--end` compile 仍 `E_DISABLED`（P6.3）  

`--json` append 未 compile：

```json
{ "session_id": "…", "buffered_turns": 3, "buffered_chars": 120, "compiled": null }
```

触发 compile 时 `compiled` 为 P6.4 的 CompileResult 形状。

无 `--json`：打印 `session_id=`；若 compiled 再打 kept paths。
