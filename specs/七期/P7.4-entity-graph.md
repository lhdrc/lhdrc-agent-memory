# Spec P7.4 — AI 建 entity + 统一建边 + 查询邻接

| 字段 | 值 |
|---|---|
| ID | P7.4 |
| 状态 | done |
| 依赖 | P3.1 抽链与 graph 臂、P6.3/P6.6 compile、P7.1（实体提议走 `complete` 已有 compile JSON）、M1 entity 文件事务 |
| 对应架构 | 08 §6.6、§7.3–7.6；六期 F12；D13 禁止只改索引 |

> 今日：`linkifyBody` 只在 compile；capture 不挂 `@slug`；模型 **不许** `entity create`（P6.6 非目标）；`graphArm` 仅关系模板句；`graph-query` 非模板空结果 exit 0。  
> 本期收回「自动建 entity」仅限 **会话 compile**；人手 capture 只挂已有实体。

## 1. 目标

1. 扩展会话提取 JSON：可选 `entities: [{ slug, title, aliases? }]`；校验后经 `EntityRegistry` **写 entity md**（D13），再 linkify  
2. `captureWrite` / 人手 `capture`：对**已有** entity 跑同一 `linkifyBody`（不调模型建实体）  
3. `hybridQuery` 的 graph 臂：无关系模板时仍用 query 里出现的 slug/title 作种子做 BFS（邻接臂），融入 RRF  
4. `graph-query` 非模板：走邻接臂并在 `--json` 标明 `mode=adjacency`；人话提示「已按实体邻接检索」，禁止只打「未能解析…空结果」  
5. unresolved：提出但 slug 非法 / 冲突时进 `unresolved`，不整场失败  

## 2. 非目标

- LLM NER 作为独立 HTTP 第二趟（优先吃 compile 同一次 JSON；不够再规定一次 `complete`，见 §3.2）  
- capture / import 自动建 entity  
- 无确认的 entity merge  
- 改 RRF `k=60`  
- 分布式图库  

## 3. 技术方案

### 3.1 提取 JSON 增量（P6.6 兼容）

`items` 不变。根级增加：

```json
{
  "entities": [
    { "slug": "alice", "title": "Alice", "aliases": ["爱丽丝"] }
  ],
  "items": [ … ]
}
```

- `entities` 缺省 / `[]`：行为与今相同（只 linkify 已有）  
- `slug`：M1 规则 `[a-z0-9][a-z0-9_-]{0,127}`；非法 → 丢该条，title 进 `unresolved`  
- 已存在 slug：不覆写 md；把 aliases **append**（去重）后重新 linkify  
- 未知 slug：`registry.create`（与 CLI `entity create` 同一写路径）  
- 模型仍禁止输出 path / wikilink / 完整 frontmatter（P6.3）  

`session-extract-v1.md` 增一小节：何时提议 entity（稳定专有名、将在 body 中提及）；不要为普通名词建实体。

### 3.2 是否第二趟 complete

默认：**同一次** compile `complete` 带出 `entities`。  
若 `items` 合法但 `entities` 缺省且 `unresolved` 将非空： **不**自动再打 LLM（避免热路径双倍费用）。P63 单测仍一次 complete。  
文档写明：实体质量靠说明书，不靠第二趟。

### 3.3 compile 写盘顺序（仍一次 `queue.execute`）

```
complete → parse items + entities
锁外：校验 slug；算哪些 create / alias-append
queue.execute 一次:
  1. 写新 entity md + alias patch（validateWrite）
  2. 读全量 entity.list()
  3. 对 pending items linkifyBody
  4. captureWrite × N
索引 hook + dirty（队列原语义）
```

entity 与 L0 同 job：中途失败已写文件留下（D1）；retry 有 extracted.json 则 **不再 complete**；extracted 须持久化 `entities` 与 items（扩展 P6.2 `extracted.json`）。

### 3.4 capture 统一 linkify

`captureWrite` 在校验后、落盘前：

```
entities = list active
{ body, links } = linkifyBody(body, entities)
frontmatter.links merge mentions
```

不调 LLM。`--json` 可含 `links: [{ to }]`（与 compile kept 对齐）。  
import / P5.8 逐行 capture 同样经过 `captureWrite` → 自动挂已有实体。

### 3.5 邻接臂

改 `graphArm`：

```
parsed = parseRelationalQuery(q)
if parsed → 现有模板 BFS（mode=relational）
else → adjacency:
  种子 = links.to_ref / entity_registry.slug|title|alias 与 query 子串命中（大小写不敏感；中文长度≥2）
  无种子 → []
  有种子 → 现有 BFS depth≤2，不强制 verb
```

`hybridQuery` 继续融合 graph 臂；非关系句 **不再** graph=[]。  
`--explain`：`arms.graph` 可非空；增加 `graph_mode: "relational"|"adjacency"|"empty"`。

RRF 权重沿用 P3.1；`k=60` 不动。

### 3.6 graph-query CLI

```
parsed 命中 → 同今，json { mode:"relational", hits }
否则 adjacency 非空 → 打印 hits；json { mode:"adjacency", hits }
否则 hits=[]；json { mode:"empty", parsed:null }
人话：mode=empty 时「未识别为关系句，且查询词未命中实体邻接；可改用 memory query」
exit 0（兼容脚本）；--json 可观测，避免误判无记忆
```

删掉唯一提示「未能解析为关系查询；返回空结果，fail-open」作为唯一输出的路径（可留在 explain 字段）。

## 4. CLI

无新子命令。`remember` / `ingest session` `--json` 的 `kept[].links` 可含新 slug；增加 `entities_created?: string[]`。
