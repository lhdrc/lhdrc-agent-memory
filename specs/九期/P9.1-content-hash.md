> 同一语义内容每次 capture 不得因时间戳改 hash，否则索引幂等失效、重复分块/嵌入。

## 1. 目标

1. `pages.content_hash` / `entity_registry.content_hash` 只对**语义稳定字段**计算。  
2. 语义不变 → hash 不变；title/body/schema_type/links/facts/aliases 变 → hash 变。  
3. 现有 M3 hash 短路测例保持绿（期望改为「语义不变跳过」）。

## 2. 非目标

- 改余弦去重（P5.1，互补）  
- 改 git dirty 判定  
- 迁移已入库的旧 hash（下次 sync 自然重算一次）

## 3. 技术方案

抽出 `semanticContentHash(raw: string): string`：

1. `parseFrontmatter`  
2. 从 frontmatter **删除**易变键后稳定序列化，再与 body 拼接做 `sha256Hex`  

**剔除（不进 hash）**：`created_at`、`captured_at`、`updated_at`、`created_by`（可选：`version` 若仅系统递增）。  

**必吃**：`title`、`schema_type`、`status`、`source`、`tags`、`aliases`、`links`、`facts`（含本期 P9.5 新增的 metric 等）、正文 `body`。  

稳定序列化：YAML 键排序或 `JSON.stringify` 对对象键排序；facts/links 数组保持文件顺序（顺序变 = 语义变）。

`sync.ts` 的 `sha256Hex(raw)` 全部改为 `semanticContentHash(raw)`。实体文件同样规则（redirect/merged 字段**要**进 hash）。

`specs/mvp/00-conventions.md` §3「内容 hash」改为指向本 Spec。
