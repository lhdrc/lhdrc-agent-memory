# Spec P9.8 — 写路径默认异步

| 字段 | 值 |
|---|---|
| ID | P9.8 |
| 状态 | done |
| 依赖 | P8.1 Job 文件形状 / `deferCompile` / `E_TIMEOUT` |
| 对应架构 | 08 §2/§6.1；TODO #41；**废止**八期 README「CLI remember 仍同步」 |
| 仓库 | JobRunner **迁入本仓 core**；CLI + 插件共用 |

> 所有写路径默认入队；要同步必须 `--wait` / `wait: true`。不能 fire-and-forget。失败不留半成品 L0。

## 1. 目标

1. `JobRunner` 从插件迁到 `packages/core`（权威仍 `.dfmemory/jobs/{brainId}/{task_id}.json`）。插件改为 import core，**禁止**第二套队列。  
2. CLI `memory capture` / `memory remember` / `ingest --adapter session` 默认入队，stdout：`accepted=true` + `task_id`（`--json` 同 P8.1 形状）。  
3. `--wait`：行为等于今日同步（写完再返回 kept/path）。测例与口令用 `--wait` 保持「立刻可 query」。  
4. `compileSession` 无 wait 时入队 kind=`compile`。人手 `capture` kind=`capture`（无 LLM，通常很快，仍走队列以统一观测）。  
5. `memory job status <task_id>` CLI（与插件 `memory_job_status` 同文件）。  
6. 无 Key 的 remember：任务 `failed` + `E_DISABLED`，不写 L0。

## 2. 非目标

- 守护进程 / Idle TTL  
- 改挂钩过滤规则（P8.1）  
- fire-and-forget 无 task_id  
- 并行 compile 同 brain  

## 3. 技术方案

### 3.1 迁移

插件 `src/jobs.ts` 逻辑下沉：`enqueue` / CAS pending→running / 超时 abort / 启动扫描 running→failed+E_JOB。  
core 导出 `enqueueMemoryJob` / `runNextJob` / `readJob`。

kind 扩展：`capture` | `compile` | `end_session` | `remember`（P8.1 已有后三个）。

### 3.2 CLI 契约

```
memory capture …              # 默认 async
memory capture … --wait       # 同步
memory remember --body …      # 默认 async（废止 P6.4 立即 compile）
memory remember --body … --wait
memory job status <task_id> [--json]
```

`--json` 异步成功：

```json
{ "accepted": true, "task_id": "…", "status": "pending" }
```

`--wait` 成功：今日 capture/remember JSON + `task_id` + `status: "done"`。

帮助文案必须写默认异步。验收口令文档（mvp README / AGENTS）capture 示例加 `--wait` 或「job done 后再 query」。

### 3.3 兼容

插件 `rememberAsync` 已默认 true，改为调 core runner。`wait: true` 不变。
