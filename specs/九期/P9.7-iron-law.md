> 提及已有实体必须在实体页留下反向链；facts 带内联来源。不扩 dream 九段。

## 1. 目标

1. capture / compile 写盘成功后：正文或 links 里指向 `entities/{slug}` 的提及 → 在该实体文件 **append** 一条 back-link（指向本节点 path），去重。  
2. 每条 fact 落盘时：若无 `[Source:` 子串，则在 `text` 末追加 ` [Source: {node path 或 title}]`。已有则不动。  
3. 实体页仍可不进 `pages`（M3）；back-link 只改实体 md。  
4. 失败 fail-open：主节点已写成功则不回滚；back-link 错误记 log / 不抛。

## 2. 非目标

- dream backlinks 段 / 九段  
- 强制所有人名为实体（不自动 create entity）  
- compiled_truth  
- 改检索 boost  

## 3. 技术方案

在 `WriteQueue.execute` 成功后的 hook（或 `captureWrite` 末尾）调用 `applyIronLaw(repoRoot, nodeRel, queue)`：

- 解析 node 的 `links[]` 与 `@slug` / wikilink  
- `resolve` 活实体  
- 读 `entities/{slug}.md`，若正文或 frontmatter.links 尚无 `to: {nodeRel}` 且 type=`mentioned_in`（或 `backlink`），则 append link，不改正文段落（减少冲突）  
- facts：对每条 `text` 做上述 Source 后缀；**同一事务**写回该节点（L0 改 facts 文本：这是 enrich 不是用户正文 ADD-only 冲突——锁定：仅追加后缀，不改 text 其余部分）

与 D17：不删、不改用户句子，只追加链接与 Source 标记。

配置：

```yaml
iron_law:
  backlink: true
  source_suffix: true
```

默认 **true**（本期产品选择）。`false` 可关。
