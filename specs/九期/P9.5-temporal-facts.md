| 字段 | 值 |
|---|---|
| ID | P9.5 |
| 状态 | ready |
| 依赖 | WRITE_FORMAT；无 facts 表（TODO #16 不做） |

| 仓库 | 本仓 core + CLI |

> 可选量纲字段进 facts；`memory trend` 扫 md 做回归检测。无量纲的旧 facts 不参与。

## 1. 目标

1. `facts[]` 增加可选：`metric`（string）、`value`（number）、`unit`（string）、`period`（string，如 `2026-Q1` / `2026-08-16`）。  
2. 缺这些字段的 facts **合法**（旧文件不坏）。  
3. `memory trend <metric> [--json]`：同 brain 内扫 `sources/**/*.md` 与 `entities/*.md` 的 facts，按 `at` 或 `period` 排序；若最新 value 比上一笔低 ≥ `threshold`（默认 0.10）→ `regressing: true`。  
4. 写入仍文件权威；不建索引表。

## 2. 非目标

- embedding drift score  
- 把趋势当 hybrid 一臂  
- facts 表 / `facts.md`（#16/#30 不做）  
- 热路径每次 capture 跑全库趋势  

## 3. 技术方案

### 3.1 WRITE_FORMAT

```ts
facts?: Array<{
  text: string;
  event_type: string;
  attributed_to: string;
  at: string;
  metric?: string;   // slug 或短名，1–64
  value?: number;    // 有 metric 时建议有；仅 metric 无 value → 不进趋势
  unit?: string;
  period?: string;
}>;
```

校验：有 `value` 无 `metric` → `E_VALIDATION`；`value` 非有限数字 → 失败。`metric` 无 `value` 允许（标记性）。

### 3.2 趋势算法

```
rows = 所有文件 facts 中 metric 规范化相等者且 value 为有限数
sort by (period ?? at) 升序
if rows.length < 2 → regressing=false, reason=insufficient
else:
  old, new = rows[-2], rows[-1]
  if old.value == 0: drop 或 skip 该对
  drop = (old.value - new.value) / abs(old.value)
  regressing = drop >= threshold
```

「恶化」默认假设 **指标越大越好**。配置：

```yaml
trend:
  threshold: 0.10
  direction: higher_is_better   # 或 lower_is_better（延迟类）
```

`lower_is_better` 时符号取反。本期只支持全局 direction，不按 metric 表。

### 3.3 CLI

```
memory trend <metric> [--threshold 0.1] [--json]
```

JSON：

```json
{
  "metric": "timeout_ms",
  "points": [{ "at": "...", "value": 2, "path": "brains/…", "text": "…" }],
  "regressing": false,
  "drop": 0.0,
  "threshold": 0.1
}
```

无点 → `E_NOT_FOUND` 或 JSON `points:[]` 退出 0（锁定：**退出 0 + 空 points**，便于脚本）。
