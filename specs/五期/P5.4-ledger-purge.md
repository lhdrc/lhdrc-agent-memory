# Spec P5.4 — Event Ledger、linkFacts 与硬删 purge

| 字段 | 值 |
|---|---|
| ID | P5.4 |
| 状态 | done |
| 依赖 | M1、M2；建议 P3.3 |
| 对应架构 | 08 §13、D13、D17 L3、D18 |

## 1. 目标（每项须 CLI 可验证）

1. **`memory events list`**：可按 type/source/from 列出 ledger 事件  
2. **`memory events append`**：高级写入一条事件（测试/运维可用）  
3. **merge / forget(soft) 自动记账**：现有操作写入可被 list 查到  
4. **`entity link-facts`**：关联写入 entity 文件 + `fact_linked` 事件；rebuild 仍在  
5. **`forget --purge --confirm`**：物理删除 + `node_purged` +（mode≠off）独立 force commit  
6. **鉴权**：非 owner 远程 token 无法 purge  

## 2. 非目标

- 自动硬删、dream 触发 purge  
- 分布式事件总线  

## 3. 技术方案

布局与类型见前版（`events/{YYYY-MM}/ledger.jsonl`）。  
软删 `forget`（无 purge）须 append `node_archived`。

```
memory events list [--source] [--from] [--type] [--limit] [--json]
memory events append --type <t> --payload-json '{}' [--json]
memory entity link-facts <slug> --fact <text> [--path <rel>] [--json]
memory forget <path>                  # soft
memory forget <path> --purge --confirm
```

## 4. 验收（须可跑）

| ID | 功能点 | Given / When / Then（口令） |
|---|---|---|
| P54-01 | list 可用 | 空 brain → `events list --json` → `{events:[]}` 退出 0 |
| P54-02 | append 可用 | `events append --type note --payload-json "{\"k\":1}" --json` → list 能查到 |
| P54-03 | merge 记账 | `entity merge a b --canonical a --confirm` → `events list --type entity_merged --json` 非空 |
| P54-04 | soft forget 记账 | `forget <path>` → 文件仍在且 archived；`events list --type node_archived` 命中 |
| P54-05 | link-facts 可用 | `entity create` + `link-facts slug --fact "已签约" --json` → entity md 含该 fact；`events list --type fact_linked` 命中；`rebuild-index` 后实体关联仍在（文件或索引断言） |
| P54-06 | purge 拒绝无确认 | `forget <path> --purge`（无 confirm）→ 非 0 + `E_USAGE`；文件仍在 |
| P54-07 | purge 可用 | `forget <path> --purge --confirm` → 文件不存在；`read` → `E_NOT_FOUND`；`events list --type node_purged` 命中 |
| P54-08 | force commit | `git.mode=batch` 且为 git 仓 → purge 后 `git log -1 --oneline` 含 purge/memory 前缀的独立提交（mode≠off） |
| P54-09 | 鉴权 | 配置 reader token → `DF_MEMORY_TOKEN=… forget --purge --confirm` → `E_FORBIDDEN` |
| P54-10 | soft 与硬删对照 | 同 path 先 soft 再（另文）purge；两者事件类型不同且可 list 过滤 |
