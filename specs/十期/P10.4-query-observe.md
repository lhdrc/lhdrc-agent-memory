# Spec P10.4 — 检索可观测（query log + explain 分母）

| 字段 | 值 |
|---|---|
| ID | P10.4 |
| 状态 | done |
| 依赖 | P3.1 `--explain`；P3.2 observer；P9.3 fusion 字段 |
| 对应架构 | 08 §7.7；TODO **#22 + #32**（同一 Spec） |
| 仓库 | 本仓 `packages/core` + CLI |

> 只记录、只展示。**不改**默认融合公式、floor、hotness α、rerank 默认关。

## 1. 目标

1. 每次 `hybridQuery`（非 cache 命中、或 cache 命中也要能记延迟）在 `.dfmemory/logs/query.jsonl` 追加 **latency_ms** 与 **各臂 evidence 计数**。  
2. `memory observer [--json]` 输出平均延迟、零结果率，以及 keyword / semantic / graph 占比。  
3. `memory query --explain --json` 补齐：`query_plan`、`searched_directories`、每条 hit 的 `score_details`（分母级）。  
4. 现有 explain 字段（intent / arms / fusion / hotness_detail）保留。

## 2. 非目标

- 改检索排序或 top-k 默认  
- 真模型 rerank 默认开  
- pgvector（#9）  
- 把 contradictions 打进 explain  
- 插件 UI；本仓 CLI JSON 即可  
- query log 当审计合规（无敏感打码，#29 不做）

## 3. 技术方案

### 3.1 query log（#22）

现网 `recordQueryStat`：`at, query, hitCount, avgScore`。

追加（缺省当 0，读旧行兼容）：

```json
{
  "at": "ISO",
  "query": "…",
  "hitCount": 0,
  "avgScore": 0,
  "latency_ms": 0,
  "evidence": { "keyword": 0, "semantic": 0, "graph": 0 }
}
```

计数规则：对 **返回的 hits**（截断后的终榜），看 `hit.evidence` 标签：

- 含 `bm25` / `keyword` → keyword++  
- 含 `semantic` → semantic++  
- 含 `graph` → graph++  

一条 hit 可计入多臂。标签以现网 `evidence` 字符串为准；若现网用别的名字，本 Spec 实现时与 `hybrid.ts` 对齐并在测例锁死。

`latency_ms`：`hybridQueryDetailed` 入口到返回的墙钟（整数）。cache 命中也记（通常很小）。

observer：

| 字段 | 含义 |
|---|---|
| `avg_latency_ms` | 有 `latency_ms` 的行的平均；旧行无该字段则不计入分母 |
| `evidence_share` | 三臂计数各自 / 三臂计数之和；和为 0 则三键皆 0 |

人类可读输出加两行即可。`--json` 必须带新键。

### 3.2 explain（#32）

`QueryExplain` 增加：

```ts
query_plan: string[];           // 有序列，见下
searched_directories: string[]; // posix 目录，最多 32 个，分高在前
score_details: Array<{
  path: string;
  kw?: number;       // 该臂 rrf' 或 0
  sem?: number;
  graph?: number;
  title?: number;
  entity?: number;
  fused?: number;    // floor 前的 final_rel
  cosine?: number;   // 未跑则为省略或 null
  hotness?: number;  // 0–1 乘子里的 hotnessBoost
  final?: number;    // 终分
  dropped?: "per_arm" | "fused_min" | null;
}>;
```

`query_plan` 锁定文案（测例可 assert 包含这些子串，允许中间多步）：

1. `intent:<task|experience|person|relation|general>`  
2. `arms:bm25,semantic,graph`（semantic 关则写 `semantic:off`）  
3. `fusion:rrf_rescale`  
4. `floor`  
5. `cosine:applied|skipped`  
6. `signals`  
7. `hotness`  
8. `prefilter:dir|off`  
9. `rerank:off|local|model|skipped`

`searched_directories`：目录预筛的 `dirs` **全量最多 32**（现网 explain 截 8 的，`--explain` 用 32）。预筛关闭时：终榜 hits 的父目录去重，仍最多 32。

`score_details` 覆盖 **终榜 hits**；被 `fused_min` 丢掉的 path **不强制**进数组（测例用「终榜每条都有 details」）。分母：rrf' 的 k=60 与 P9.3 一致，details 里写 rescale 后的值，并在 fusion 块保留现网 `per_arm_min` / `fused_min`。

CLI：`--explain --json` 把上述字段放在现网 explain 对象内（不要另包一层导致旧脚本全挂；允许加键）。

### 3.3 性能

无 `--explain` 时仍算 score_details 的重字段 **禁止** 默认全开；终榜条数通常 ≤ limit（默认 10）。log 的 evidence 只扫终榜。

## 6. 验收

| ID | Given / When / Then |
|---|---|
| P10Q-01 | 一次 hybridQuery 后 log 最后一行有 `latency_ms` ≥ 0 且为 number |
| P10Q-02 | 夹具能打出 BM25 命中 → 该行 `evidence.keyword` ≥ 1 |
| P10Q-03 | observer --json 含 `avg_latency_ms`、`evidence_share.keyword` |
| P10Q-04 | 仅旧格式 log（无 latency）→ observer 不崩溃；`avg_latency_ms` 为 0 或省略分母 |
| P10Q-05 | `--explain --json` 含 `query_plan` 数组且含 `fusion:rrf_rescale` |
| P10Q-06 | 终榜每条 path 在 `score_details` 有 `final` |
| P10Q-07 | `searched_directories` 为字符串数组（可空） |
| P10Q-08 | 不传 `--explain` 的 query JSON **无** 强制要求客户端看到 score_details；现网无 explain 测例仍绿 |
| P10Q-09 | P9.3 explain 的 `fusion.rescale` / `hotness_detail` 仍在 |
