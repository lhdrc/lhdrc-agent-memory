## 0. 现状（为什么不能现在发数）

现网 `evals/adapter-run.ts` + `adapters/locomo.ts`：

1. 每句对话 `captureNode` 成 `note`（零 LLM，不是记忆系统）。  
2. `hybridQuery` 后用 gold **子串**是否出现在命中里打分。  
3. 不排除 category 5；不答题、无 LLM judge；receipt 无 token / 延迟 / 数据 pin。  
4. 评测临时仓 `init` 默认 `embedding.provider: openai`，CI/无 Key 时 **fail-open 哈希**。语义臂从未用真模型做过活测（P9.2 测例是 `local` / mock / 假 fetch）。

因此：`memory eval --adapter locomo --fixture` 只能证明夹具形状，**不能**当对外 J-score。

## 1. 目标

1. 锁定一条可对外报的 LoCoMo **J-score** 协议（写入 / 检索 / 答题 / judge / 计分范围）。  
2. 给出 **评测前检查单**（G0–G6）：未过门闩禁止全量跑、禁止发数。  
3. 实现 publish runner：按 session `compileSession` → `hybridQuery` → answerer → judge；支持 resume；写出带 pin 的 receipt。  
4. `--fixture` 行为与 P56-05 **不变**（无网、子串、退出 0）。

## 3. 发数合同（已锁定）

对外任何「我们 LoCoMo = x%」必须同时满足下表。改任一项 = 新口径，须重跑并改 receipt pin。

| 项 | 锁定 |
|---|---|
| 数据 | `locomo10.json`；URL 默认见 `evals/fetch.ts` `LOCOMO_FULL_URL`；receipt 写 **URL + sha256** |
| 计分题 | **只评 JSON `category` ∈ {1,2,3,4}**（约 1540 题）。**排除 5**（adversarial，无可靠 gold） |
| 类别名 | `1`=multi-hop，`2`=temporal，`3`=open-domain，`4`=single-hop。**禁止**按论文正文 (1)(2)(3)(4) 顺序当 JSON 数字 |
| 隔离 | 每个 `sample_id` 独立临时仓（或独立 brain）。样本之间记忆不得串 |
| 写入 | 每个 `session_N` → inbox turns（`speaker`→role 映射见 §5.2）→ **`compileSession`（`--wait` 语义，同步）**。禁止整场 transcript dump 进 `brains/*/sources/` |
| 无 Key | compile `E_DISABLED` → 该 sample **整组不计分**，receipt 记 `compile_failed`；**禁止**退回 `capture` |
| 蒸馏 | 评测仓 **关** `distill` / 懒蒸 / 自动结晶（`kill_switch.distill: true` 或 `lazy_min_sources` 极大）。发数测 L0 写入+检索，不测蒸馏飞轮 |
| 检索 | 现网 `hybridQuery`；`excludeSchemaTypes: ["skill"]`；`excludeSidecars: true`；**top-k=10**；`mode: balanced` |
| 注入答题器 | 命中的 `title` + `snippet`（及有则 `abstract`）。**不**对每条 hit `readNode` 全文（锁成本与口径） |
| 答题 | `complete({ purpose: "other" })`；temperature 0；只根据检索记忆答题；prompt 见仓内锁文件 |
| Judge | 二进制 CORRECT/WRONG；只看 question / gold / predicted；**不见** evidence dialog id。解析失败 = WRONG |
| 模型 | 答题/judge/compile 默认 **`deepseek-ai/DeepSeek-V4-Flash`**；embedding **`Qwen/Qwen3-Embedding-8B`**（dims=4096）。网关默认 `https://api.siliconflow.cn`（OpenAI 兼容）。可用 `DF_EVAL_CHAT_MODEL` / `DF_EVAL_EMBED_MODEL` / `DF_EVAL_API_BASE` 覆盖。receipt 分开记 |
| 报告 | 总分 + 四类分项 + 每问注入 token（答题 prompt）+ compile/judge token + p50/p95 延迟 + 上述 pin |

同表必须声明 **未测**：LongMemEval、HaluMem、category 5。禁止与 Mem0 92.5 / MemOS 88.83 做无协议对比。

## 4. 评测前检查单（操作门闩）

全量跑之前按序做完。G0 是代码；G1–G6 是发数操作。任一未过 → 禁止把数字对外。

### G0 — 代码已按 §5 落地（开发）

Given 本仓已实现 publish runner 与测例。  
When `bun test packages/core/tests/` 中 P10.1 相关测例绿，且 P56-05 仍绿。  
Then 才能进入 G1。空 stub / 仍用 `captureNode` 打全量 = 未过。

### G1 — 密钥与模型

需要同一把兼容 Key（优先 `DF_EVAL_API_KEY` / `SILICONFLOW_API_KEY`，否则 `OPENAI_API_KEY`）：

| 用途 | 配置 | 缺了会怎样 |
|---|---|---|
| compile | `llm.provider: openai` | `E_DISABLED`，不能发数 |
| answerer / judge | 同上 `complete()` | 不能出 J-score |
| embedding | `embedding.provider: openai` | fail-open **哈希**，语义臂弱，数字必须标 `embedding_fallback: local`，**不建议对外当主分** |

Judge / 答题 / compile 默认同一聊天模型 `deepseek-ai/DeepSeek-V4-Flash`；embedding `Qwen/Qwen3-Embedding-8B`。网关默认硅基流动。

### G2 — 真 embedding 活测（必须，CI 从未做过）

评测仓（或一次性临时仓）在 **有 Key** 时：

```bash
# 确认 memory.yml：embedding.provider: openai，且未降级
bun run memory -- capture --wait --title "embedding-smoke" --type note --body "Mochi is a corgi adopted last Tuesday."
bun run memory -- query "What dog was adopted?" --explain --json
```

**过门**：explain **无** `embedding_fallback: local`；semantic arm 非空；chunk 向量维度与 `dims: 1536` 一致（mismatch 则先 `rebuild-index --embeddings`）。  
**不过**：无 Key、fallback 哈希、semantic 空、或 provider 仍 `local` → 先修环境，不准全量。

### G3 — 拉数据并 pin

```bash
bun run memory -- eval fetch --adapter locomo --allow-net
```

对 `evals/cache/locomo/data.json`（或 `DF_EVAL_CACHE_DIR`）算 **sha256**，写入本轮 receipt 模板 / 运行日志。URL 必须与 `LOCOMO_FULL_URL` 一致（可用 `DF_EVAL_LOCOMO_URL` 覆盖，覆盖也要记进 receipt）。

未 fetch → 现网 P56-06：非 0 + 提示 `--fixture` 或 `fetch --allow-net`。

### G4 — 单 sample 预跑（成本探针）

用 publish 协议只跑 **一个** `sample_id`（CLI `--sample <id>` 或等价）。核对：

1. 该 sample 的 `session_*` 均经 compile，L0 有 decision/lesson/note，**不是**逐句 raw transcript。  
2. QA 中 category 5 不出现在计分 `n`。  
3. 每题有 predicted、verdict、retrieved paths。  
4. `.dfmemory/costs.jsonl`（或 receipt token 字段）有 compile / complete / embedding 用量。  
5. 无 Key、compile 失败时该 sample 被标记失败而非 0 分灌水。

预跑费用应远小于全量（约 1/10 对话）。此步用来估全量墙钟与账单，并暴露抽取合同在对话数据上的问题。

### G5 — 评测仓开关（全量配置）

临时仓由 runner 创建，**不要**用开发者日常仓。锁定：

```yaml
embedding:
  provider: openai
  model: Qwen/Qwen3-Embedding-8B
  dims: 4096
  base_url: https://api.siliconflow.cn
llm:
  provider: openai
  model: deepseek-ai/DeepSeek-V4-Flash
  base_url: https://api.siliconflow.cn
  distill: false
  kill_switch:
    distill: true
    compile: false
compile:
  window_max_turns: 0         # 每个 locomo session 一次 compileSession，不走滑动窗切碎
  # 若实现选择 window>0：必须在 receipt 声明切窗，视为口径变体
distill:
  lazy_min_sources: 9999
  auto_crystallize: false
search:
  mode: balanced
cost:
  daily_token_cap: 0          # 发数跑不要被日 cap 腰斩；用量仍写 jsonl
```

`window_max_turns: 0` 若与现网「≤0 表示未开窗」冲突：runner 对每个 `session_N` **直接** `compileSession({ turns })`，不调用 `appendSessionTurns`。这是推荐实现（§5.2）。

### G6 — 声明本轮 pin 后才全量

全量命令（见 §7）启动前，操作者确认 receipt 将写入：

- dataset URL + sha256  
- answerer / judge / compile 模型 id  
- embedding provider + model + **是否 fallback**  
- prompt 文件 hash（答题 + judge）  
- top-k、exclude skill/sidecar、蒸馏关闭  

然后跑全量。支持 **resume**（按 sample_id 跳过已 compile 且已 judge 的样本）。断线重跑不得丢已写入的 per-question 明细。

**全量完成后**：`eval:report` 能打印最近 locomo publish receipt。数字进 README 前再人工对一遍 §3 表。

## 5. 技术方案

### 5.1 模块落点

| 模块 | 路径 |
|---|---|
| 协议常量 / 类别映射 | `evals/adapters/locomo.ts`（扩展，保持 `--fixture` load 兼容） |
| 答题 + judge prompt（锁进仓） | `evals/adapters/locomo-prompts.ts`（或 `.md` + 导出字符串） |
| publish runner | `evals/locomo-publish.ts`（由 `adapter-run.ts` 在 **非** `--fixture` 时调用） |
| 单题明细 / resume 状态 | `evals/cache/locomo/runs/<run_id>/`（gitignore，与 `data.json` 分开） |
| CLI | `evals/run.ts`、`evals/lib/argv.ts`、`packages/cli/src/commands/eval.ts` |
| 测例 | `packages/core/tests/p101_locomo_publish.test.ts`（hermetic：mock `complete` + mock embedder） |

`--fixture` 继续走现网 `adapter-run.ts` 的 `captureNode` + `goldHit`，**不**走 publish runner。

### 5.2 写入映射

LoCoMo `session_N[]` 每条 `{ speaker, text, dia_id? }`：

- 偶数/先发言者（`speaker_a`）→ `role: "user"`，另一人 → `role: "assistant"`（或按 `speaker_a`/`speaker_b` 名字匹配）。  
- 每条 turn 的 `text` 原样进入 inbox（可前缀 `SpeakerName: ` 以免抽空归属）。  
- `session_N_date_time` 写入该次 compile 的系统侧上下文或第一条 system/user 行，便于 temporal 题。  
- **一个** `session_N` = **一次** `compileSession`。session 之间按时间顺序，后者可 prefetch 已有记忆（现网 compile 行为，保留）。  
- 忽略图片 URL / blip_caption（非目标；不把多模态当记忆）。

`compileSession` 必须注入评测仓的 openai `LLMProvider`（与产品路径同一 `complete({ purpose: "compile" })`）。同步等待 kept；异步 JobRunner **不**用于发数热路径（避免超时/竞态）。

### 5.3 答题 / judge

- 答题 prompt：question + 编号记忆列表（path/title/snippet）。模型只输出答案正文。  
- Judge prompt：行业 J-score（CORRECT/WRONG）；可参考 mem0 `memory-benchmarks` 的宽松语义重叠条款，但 **全文锁进本仓** 并 hash。改字即新口径。  
- 均经 `complete({ purpose: "other" })`。temperature：实现上 OpenAI 请求须能传 0；若现网 `OpenAILLMProvider` 写死非 0，本期允许给 eval 一条窄路径（query param 或 eval 自建 chat 调用），**禁止**为了评测改生产默认温度。  
- 解析：judge 文本含 `CORRECT` 且不含 `WRONG` 为 1，其余 0（含 JSON 包裹时优先读字段）。失败 = 0。

### 5.4 计分

```
n     = 题目数 where category ∈ {1,2,3,4} 且所属 sample 未 compile_failed
hits  = verdict==CORRECT 的题数
accuracy = hits / n          # n=0 则 receipt ok=false，不报 100%
per_category[1|2|3|4] = 同类 accuracy
```

`--fixture` 的 `ok: accuracy>=1` **不**用于 publish。publish 的 `ok` = 跑完且 `n` 达到预期下限（全量 `n>=1500`；`--sample` 预跑 `n>=1`）且无未捕获异常。准确率高低不决定退出码（避免 65% 被当成脚本失败）；脚本失败仅：缺数据、缺 Key、G2 式 fallback 在全量模式未 `--allow-hash-embed`。

全量默认 **拒绝** embedding fallback：若 resolveEmbedder `fallback=true`，启动即非 0。预跑/调试可显式 `--allow-hash-embed`（receipt 必标，禁止当对外主分）。

### 5.5 Resume

状态文件按 `sample_id` 记录：`compiled` | `qa_done` | `failed`。  
`--resume <run_id>` 跳过已 `qa_done` 的 sample。compile 失败可对该 sample `--retry-sample`。

## 6. CLI 契约

```
memory eval --adapter locomo --fixture          # P5.6 不变
memory eval fetch --adapter locomo --allow-net  # P5.6 不变
memory eval --adapter locomo [--json]           # 全量 publish（需已 fetch）
memory eval --adapter locomo --sample <id>      # G4 预跑
memory eval --adapter locomo --resume <run_id>
memory eval --adapter locomo --allow-hash-embed # 仅调试；receipt 标 fallback
```

| 条件 | 退出码 |
|---|---|
| `--fixture` 且夹具命中（P56-05） | 0 |
| 全量未 fetch | 1，消息含 `fixture` 或 `fetch --allow-net` |
| 全量且无 LLM Key | 1，`E_DISABLED` |
| 全量且 embedding fallback、无 `--allow-hash-embed` | 1 |
| 全量/预跑正常结束 | 0（与 accuracy 无关） |
