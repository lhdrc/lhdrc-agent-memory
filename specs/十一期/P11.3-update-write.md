## 1. 目标

1. 提取合同：prefetch「已在知识库」若是 **同一槽位的旧值**，必须再 emit 新 item，禁止 skip。  
2. 余弦去重：相似度 ≥ 阈值 **且** 判定为同一断言 → 仍跳过；宾语（数字/地点/专名）冲突 → **写入**。  
3. 新 item 可选 `facts[].supersedes`（旧 path 或旧 fact 文本截断）；`at` / `period` 沿用 P9.5。  
4. capture / compile 仍只建新节点或 append 新文件，**不改**已有 source md 正文。  
5. 测例不依赖真网 LLM（mock complete + 启发式去重夹具）。

## 2. 非目标

- 通用 `updateNode` / 覆盖写旧 note  
- 蒸馏 `experience_merge` 改语义（仍 P9.9）  
- 实体槽位 patch（P11.5）  
- 改 HaluMem 官方 judge 协议  

## 3. 技术方案

### 3.1 提取合同（`session-extract-v1.md`）

在「Already in the knowledge base」后追加锁定句（中英各一句即可）：

- 若已有条目与本轮 **同一主语、不同取值**（住址/职位/配额/开关等），视为 **更新**：必须再输出一条新 item，标题写成变更本身。  
- 不得因为 prefetch 里出现近义旧句而 skip。  
- 仍禁止复述与已有条目 **取值相同** 的事实。

P6.6 类型合同不改。P8.4 粒度不改。

### 3.2 去重：同一断言 vs 变更

`checkDedupe` 在 cosine ≥ `dedupe_cosine` 时增加 **冲突检测**（零 LLM）：

对候选文本与当前文本：

1. 抽出「值 token」：连续数字；长度≥2 的拉丁专名；常见地名/中文 2–4 字专名窗口可简化为 **数字 + 大写拉丁片段 + 引号内片段**。  
2. 若两边都有值 token，且集合 **相交为空**（双方都有值但无共同值）→ `duplicate: false`，`skipped_reason` 不置，调用方照常写。  
3. 若无值 token 可比较 → 维持现网（≥阈值即 duplicate）。  
4. `dedupe_cosine≤0` 或 embedding off → 现网（不判 duplicate）。

不要求 NER。测例用「Alice lives in New York」vs「Alice lives in San Francisco」mock 高余弦。

### 3.3 `supersedes` 字段（可选）

WRITE_FORMAT `facts[]` 增可选：

```yaml
facts:
  - text: "Alice lives in San Francisco"
    supersedes: "Alice lives in New York"   # 旧 fact 文本或仓内相对 path
    at: "2026-08-01"
```

校验：字符串，≤500；非法则丢该键，不整单失败（fail-open）。检索本期 **不读** `supersedes`（P11.4 用 contradictions；本字段给审计与后续）。

### 3.4 prefetch

`prefetchExistingMemories` 行为不变（仍只提供标题/摘要）。合同负责让模型输出新 item。测例：mock LLM 在 system/user 含 Already in KB 旧句时，仍返回新 SF item → 落盘 path 存在且正文含新值。
