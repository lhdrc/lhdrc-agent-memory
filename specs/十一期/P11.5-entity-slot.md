> 「现在住哪 / 谁任职」写在 **实体 facts** 上允许 patch。L0 `sources/` 仍只增。`note: patch` 继续不驱动 capture。

## 1. 目标

1. `entity link-facts`：若新 fact 与已有某条 **同一槽位**（启发式，零 LLM），则 **覆盖该条 text**（及 `at`），不无限 append 重复槽。  
2. 不同槽位仍 append。  
3. pack 增加 `merge_op.entity: patch`（缺省 patch）。`immutable` 则本 Spec 退回只 append。  
4. pack 注释明确：`note: patch` **L0 不读**。  
5. 人手 `capture` note 不因本 Spec 改已有 note（P99-04 回归）。

## 2. 非目标

- 通用 `updateNode`  
- compile 热路径自动 upsert 实体槽（可在 enrich 调用 link-facts，但 **本期不强制** compile 接线；CLI `entity link-facts` 先绿）  
- 两实体 `entity merge` 语义变更（canonical 合并保持 M1）  
- 用 LLM 抽槽位名  

## 3. 技术方案

### 3.1 同一槽位启发式

对已有 `facts[].text` 与新 `fact` 字符串：

- 去掉数字与长度≥2 的拉丁 token 后，剩余字母/汉字 **trigram Jaccard ≥ 0.5** 且两边都含至少 1 个「值 token」（定义同 P11.3：数字或拉丁专名）且值 token 集合不同 → 视为同一槽位更新。  
- 否则 append。  
- 文本全等 → 不写（幂等）。

例：`Alice lives in New York` vs `Alice lives in San Francisco` → patch。  
`Alice lives in New York` vs `Alice works at Acme` → append。

### 3.2 写语义

patch 时：替换命中那条 `facts[i].text`，`at` 更新为现在（ISO）；保留 `event_type` / `attributed_to` / `path`。写 `fact_linked` 事件，payload 含 `op: patch`（旧事件无此键，读取 fail-open）。

`merge_op.entity === "immutable"` → 永不 patch，只 append（与现网 P5.4 相同）。  
`append` → 只 append。  
未知串 → append + warn（对齐 P9.9）。

### 3.3 pack

`packages/core/schema-packs/problem-tree.yml`：

```yaml
merge_op:
  requirement: immutable
  decision: append
  lesson: append
  experience: append
  note: patch          # L0 不读（P9.9 / P11.5）；仅文档占位
  entity: patch
```

`specs/mvp/schema-packs/problem-tree.yml` 同步一句注释，避免两份长期漂移（若测试只读 core 包，以 core 为准）。

## 5. CLI

现网：

```
memory entity link-facts alice --fact "Alice lives in San Francisco" --json
```

第二次不同城市 → 实体文件 **facts 条数不增加**，text 为新值。`--json` 可含 `patched: true`。
