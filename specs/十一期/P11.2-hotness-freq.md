> 第一步只加 **访问频率**。α、乘法、半衰期默认 30 天不改。无计数时行为 = 现网。

## 1. 目标

1. `h = freq * recency`，其中 `recency = exp(-ln2 * ageDays / half_life_days)`（现网）。  
2. `freq = sigmoid(log1p(n))`，`n` = 该 path 进入 hybrid **终榜** 的次数。  
3. `n=0` 或计数不可用 → **freq=1**（P9.3 夹具同分序）。  
4. 仍 `score = rel * (1 + α * h)`，α 默认 **0.15**。  
5. query log 或独立 counter 能还原 n；失败 fail-open 当 n=0。  
6. `--explain` 可见 `hotness.freq` / `active_count`（终榜每条不必强制，explain 块有模式即可）。

## 2. 非目标

- 把 α 拧大当更新语义  
- 加法 0.45  
- 按访问删除/归档  
- 把 contradictions 乘进 hotness（归 P11.4）  
- 改三臂 RRF / sigmoid 融合（P9.3 已禁融合 sigmoid；此处 sigmoid **只**用于 freq∈(0,1)）

## 3. 技术方案

### 3.1 公式

```
recency(path) = exp(-ln2 * ageDays / max(1, half_life_days))   # 无 updated_at → 0.5，现网
freq(path)    = n <= 0 ? 1 : 1/(1+exp(-log1p(n)))            # sigmoid(log1p(n))
h             = freq * recency
score         = rel * (1 + α * h)
```

`n=1` 时 freq≈0.73，故 **有过命中的文档** 比「从未进终榜」略弱于纯 recency=1 的新文档——这是刻意：冷启动仓（评测第一次 query）全部 n=0 → 全员 freq=1 → 与现网一致。

同一会话内多次 query：先命中的 path n 增加，后续 query 才体现频率。单次 query 内不把本次终榜计入本次排序（先排后 +1）。

### 3.2 计数存储

优先独立文件，避免把 path 列表塞进每行 query.jsonl 撑爆：

`.dfmemory/logs/hit-counts.json`（brain 内 path → 整数）。格式：

```json
{ "v": 1, "counts": { "brains/default/experiences/a.md": 3 } }
```

hybridQuery 成功返回后，对终榜 path 各 +1（同步追加允许；失败吞掉）。P10.4 `query.jsonl` **不必须**改形状；可选 debug 字段 `top_paths` 不进 DoD。

无文件 / JSON 坏 / 写失败 → n=0，query 仍成功。

### 3.3 配置

```yaml
search:
  hotness:
    enabled: true
    half_life_days: 30
    alpha: 0.15
    freq: true    # false 则 freq 恒 1（现网）
```

`freq: false` 供对照实验。默认 **true**（n=0 时无差别）。

### 3.4 explain

```json
"hotness": true,
"hotness_detail": { "alpha": 0.15, "mode": "multiply", "freq": "applied"|"identity" }
```

`freq: identity` = 本轮所有 hit n=0 或 `hotness.freq=false`。
