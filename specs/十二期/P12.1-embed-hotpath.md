> GroupMemBench（~6 万 chunk × 4096 维）证明 JS 全表余弦 + 拉全文不够用。  
> 本期把 **O(n) 扫描变便宜、可续跑、可重试**。不替代 **#9** ANN。

## 1. 目标

1. 语义臂打分 SQL **只读** `path`（或 chunk id）+ `embedding`；winner 再取 `text` / `title` 做 snippet。  
2. BYTEA 用 **`Float32Array` 视图**（对齐则零拷贝），避免每条拷成 `number[dims]`。  
3. `rebuild-index --pending-embeddings`：只填 `embedding IS NULL`，**不清** pages/chunks。  
4. openai-compatible embeddings：**429 / 5xx** 有限次退避重试。  
5. 长驻进程可按 `repoRoot` + brain 缓存向量；指纹变则失效。一次性 CLI 进程退出则无增益。

## 2. 非目标

- postgres `vector` 列 / HNSW / `<=>`（**#9**）  
- 改变 RRF / cosine_lambda / hotness 公式  
- 把评测 `query_loop` 做成 CLI 默认命令  
- 配置 CLI（见 P12-config-cli，本期只方案）

## 3. 技术方案

### 3.1 打分 I/O

`semanticArm`：

1. `SELECT c.id, c.path, c.embedding FROM chunks c JOIN pages p … WHERE embedding IS NOT NULL`（保留既有 page 过滤）。  
2. 同 path max-pool（仍按 cosine）。  
3. 仅对 top `limit` 的 winner id：`SELECT c.id, c.text, p.title FROM … WHERE c.id IN (…)`。  
4. snippet 仍用 winner chunk 的 `text` + `makeSnippet`。

排序与 evidence 与现网一致。缺 title 时用 path basename 即可。

### 3.2 数值

- 新增（或改）`bytesToFloat32View(buf) → Float32Array`：`byteOffset % 4 === 0` 则 view，否则拷到对齐缓冲。  
- `cosineSimilarity` 接受 `ArrayLike<number>`（`number[]` 与 `Float32Array`）。  
- `bytesToFloat32` 保持可用（可经 view 再拷 `number[]`），既有 P21a 测例绿。  
- 查询向量每臂转换 **一次** `Float32Array`。

小端（LE）与现网 `DataView.getFloat32(..., true)` 一致；目标运行时均为 LE。

### 3.3 进程内缓存

- key：`repoRoot` 正规化 + `brainId` + 过滤指纹（source/schema/path 前缀等）。  
- 有效性：同一过滤下 `COUNT(*)` + `SUM(length(embedding))`（或等价）未变则命中。  
- 命中则跳过打分 SELECT，仍要拉 winner text（text 不进缓存，避免把正文堆进长驻内存）。  
- `rebuildIndex` / `--pending-embeddings` 成功后主动 `invalidate`（指纹也会变，主动清更稳）。  
- CLI 一次性进程：无二次增益，允许实现存在。

### 3.4 续跑 embedding

**写路径 `syncPage`**：page + chunks（无向量）**先 COMMIT**；再 `UPDATE embedding`。embed 失败 **不回滚** 已提交的 page/chunks（chunk 保持 `NULL`），错误仍抛给调用方。禁止再把「整页 + 向量」捆在同一事务里（失败即该页索引作废，续跑无从填 NULL）。

**CLI**：

```
memory rebuild-index [--embeddings] [--pending-embeddings] [--json]
```

| 旗标 | 行为 |
|---|---|
| （无） | 现网：clear brain 索引 + `syncAll`（provider≠off 时仍会 embed） |
| `--embeddings` | 现网：clear + 全量重算向量（strict：缺 key → `E_DISABLED`） |
| `--pending-embeddings` | **不清**；`SELECT` 该 brain 下 `embedding IS NULL` 的 chunk，按批 `embed` + `UPDATE`；strict 同 `--embeddings` |
| 两旗标同时 | `E_USAGE` |

`--pending-embeddings` 批大小实现自定（建议 32–64 条/次 `embed()`）。已有向量的 chunk 不动。0 条 NULL → 成功、计数 0。

`provider=off` + `--pending-embeddings` → `E_DISABLED`。

JSON：`{ rebuilt, fileCount, pendingEmbedded?: number, embeddings?: boolean }`。

### 3.5 网关重试

`OpenAIEmbedding.embed`：

- URL：`{base_url}/v1/embeddings`。`embedding.base_url` 缺省 `https://api.openai.com`（与 LLM 兼容网关同形）。  
- 对 **429** 与 **5xx**（含 500/502/503/504）：最多 **4** 次尝试（1 次原始 + 3 次重试），指数退避（实现可注入 `sleep` / `fetch` 以便测例 0 延迟）。  
- 4xx（非 429）、缺 key、JSON 形状错误：**不**重试。  
- 测例禁止出网：注入 `fetch`。

### 3.6 配置增量

```yaml
embedding:
  base_url: https://api.openai.com   # 可选；兼容网关改此
```

不改默认 provider。无此键时行为与现网 URL 一致。

## 5. 验收

| ID | Given / When / Then |
|---|---|
| P121-01 | 同一组 float32 字节：`bytesToFloat32View` 与 `bytesToFloat32` 余弦（对固定 query）一致（误差 ≤ 1e-5） |
| P121-02 | provider=local 仓：`semanticArm` 仍能按 cosine 排出相关 path；hybrid P21a-02 回归绿 |
| P121-03 | 打分查询的 SQL **不含** `c.text` / `p.title`（测例包装 `db.query` 断言）；winner 后查询才含 text |
| P121-04 | 两 chunk 同 brain：第一次 `semanticArm` 打分 SELECT 执行；同一 `db` 包装计数下第二次打分 SELECT 次数为 0（缓存命中）；改 NULL 再填后缓存失效、第三次会再打分 SELECT |
| P121-05 | provider=off capture → chunks.embedding 全 NULL；改 `local` 后 `rebuildIndex({ pendingEmbeddings: true })`：pages 行仍在（path 集合不变）、embedding 非空；**没有**走 clear（可用包装/间谍断言未调 `clearBrainIndex`，或比对 pages.updated_at 未被全表抹掉后重插的语义：path 集合 + content_hash 不变） |
| P121-06 | `--embeddings` 与 `--pending-embeddings` 同时 → CLI `E_USAGE` |
| P121-07 | 注入 fetch：第一次 500、第二次 200 合法 JSON → `embed()` 成功且 fetch 调用 2 次；第一次 400 → 不重试、抛 `E_INDEX` |
| P121-08 | `syncPage` 在 embedder.embed 抛错时：pages/chunks 行已在，embedding 为 NULL（事务已提交正文索引） |

检索/嵌入测例 **不得出网**。CI 仍 `embedding.provider: local`。
