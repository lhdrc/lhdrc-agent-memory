> 已实测：本仓 PGlite 0.3.16（PG17.5 + pgvector 0.8.0，自带 `vector` 扩展）建 HNSW 索引 + `ORDER BY v <=> $1::vector` + `EXPLAIN` 走 `Index Scan` 全通。不用 IVF（要训中心、运维重）；HNSW 免训练、增删友好，正配 `syncPage` 语义。

## 1. 目标

1. `chunks` 加 `vector(dims)` 列（现 BYTEA 保留当回退）；`USING hnsw (embedding vector_cosine_ops) WITH (m=16, ef_construction=64)`；SQL 参数一律 `$1::vector` 显式转型（实测坑，模板写死）。
2. 开库加载扩展：pglite 侧 `extensions: { vector }`；postgres 侧要求服务端装 pgvector（缺失则 fail-open）；同一套 SQL 双引擎。
3. `semanticArm` 先走 HNSW 索引，失败（扩展缺失/向量缺失）回退暴力 cosine（现逻辑原样保留当保底）。
4. 换 provider 致 dims 变更沿用 `embeddingMetaMismatch → rebuild`，不新增状态机。

## 2. 非目标

- IVF（`ivfflat` 需训 lists，分布一变重训，不做）
- 量化/Matryoshka（万篇规模再说）
- 删除暴力保底

## 3. 技术方案（对标 `index/schema.sql` / `index/engine.ts:35` `openPgliteEngine` / `retrieve/semantic.ts:47` `semanticArm` / `index/sync.ts:191` 向量分事务）

| 项 | 做法 | 文件 |
|---|---|---|
| 列/索引 | `vector(dims)` 列 + HNSW 索引；`ensureSchema` 幂等；`rebuild-index` 回填 | `index/schema.sql` + `index/engine.ts` |
| 查询 | `ORDER BY embedding <=> $1::vector LIMIT n`，异常回退暴力 | `retrieve/semantic.ts` |
| 写入 | `syncPage` 向量分事务内双写（BYTEA + vector 列）或单写 vector 列（实施定稿；推荐双写保回退） | `index/sync.ts` |

## 4. 模块落点

| 模块 | 路径 | 备注 |

| 表/索引/扩展 | `index/schema.sql` + `index/engine.ts` | 双引擎同一 SQL |
| 召回 | `retrieve/semantic.ts` | 索引优先 + 暴力保底 |
| 写入 | `index/sync.ts` | 向量列双写 |
